# 需求:「換做法到底有沒有真差別」+「鬆緊設定的代價試算」

> 2026-07-19,由使用者口述整理(feature 粒度)。

## 1. 使用者是誰 / 情境 (Persona & Context)

我是產線視覺檢測的資料負責人。平常兩件事最常發生:

- **換做法**:我會換模型、換設定、換配方(例如換一顆 embedding 模型、改校準方式、
  改取樣策略),然後看報表數字比較高就想採用。但同一份資料重跑幾次,數字本來就會
  有高有低,我根本分不清「這次比較好」是真的還是運氣。
- **調鬆緊**:瑕疵偵測有個鬆緊設定(判多嚴才算異常)。漏掉一個真瑕疵,後段才發現,
  代價可能是報廢整批、被客戶退貨;多抓幾張誤報,只是我多花幾秒人工看一眼。
  兩種錯的代價差非常多,但現在工具只給我一個「平衡」的建議,沒辦法讓我把
  「漏檢貴很多」這件事放進去試算。

另外我的資料**整批相關**:同一片晶圓切出來的影像、同一天同一台機拍的照片,
彼此像得很。我被騙過:兩個做法的差異其實只是「這批剛好比較髒」,不是做法真的不同。

## 2. 想達成的目標 (Jobs to be done)

- 我想要**把兩種做法的結果放在一起,工具直接告訴我「這差異可信/不可信」**,
  這樣我就能決定要不要換,不用憑感覺猜。
- 我想要它**講人話**:不只給一個數字,還要告訴我「差多少」「憑幾筆資料說的」,
  差異很小或資料太少就老實說「看不出來」,這樣我就不會被小樣本騙。
- 我想要工具**自己防批次效應**:我的資料有批次/晶圓/日期這種分組時,它要把
  「整批一起好、整批一起壞」考慮進去,別把批次差異當成做法差異,這樣我才敢
  拿結論去說服主管。
- 我想要**輸入我自己的成本比**(例如「漏檢一個 = 誤報五十個」),然後看
  **不同鬆緊設定下大概要付出多少代價**,這樣我就能挑一個我能接受的設定。
- 我想要它**只給我試算和建議,不要自動改我的設定**——最後用哪個是我的決定,
  我要能跟現場的人交代「這是我選的,理由是這個試算」。

## 3. 痛點 (Pain points)

- 現在換不換做法靠「跑一次看數字」,被運氣和批次效應騙過不只一次;
  說服主管時拿不出「這是真差異」的依據,常被一句「再多跑幾次看看」打回來。
- 鬆緊設定現在是憑感覺調:調太嚴怕漏,調太鬆人工看不完。沒有任何地方讓我
  把「漏檢貴很多」這個現實放進去算,只能兩邊都怕。
- 最討厭的是工具**自作主張**:我怕它哪天自動幫我改了設定,現場出事沒人知道為什麼。

## 4. 使用者眼中的「成功」(可被觀察)

- 我把兩個做法的結果選好、按一個鈕,**畫面直接出現一句結論**:
  「A 比 B 好 X(差多少),這個差異(以目前 N 筆資料)可信/看不出來」。
- 資料太少或差異太小時,它**明說「看不出來」**,而不是硬給我一個誰比較好。
- 我的資料有批次欄位時,結論旁邊**看得到它有把批次考慮進去**(例如寫明
  「已按晶圓分組比較」);沒有批次欄位時它也老實說「未考慮批次,結論僅供探索」。
- 成本試算:我輸入成本比後,**看得到一條「鬆緊 vs 預期代價」的曲線**和一個
  「以你的成本比,代價最低的設定在這附近」的標記;我改成本比,曲線跟著變。
- 它**從頭到尾沒有動過我現在生效的任何設定**;試算頁關掉再開,我的偵測結果不變。
- 這兩個功能都在我平常用的畫面裡就找得到(不用去翻另一個程式或匯出資料算)。

## 5. 不在乎 / 可放棄的 (Non-goals)

- 我不在乎統計名詞(p 值、檢定名稱)有沒有顯示——藏在「詳細」裡就好,
  主結論要講人話。
- 我不需要它支援「三個以上做法一次比」——兩兩比就夠我用了。
- 我不需要它自動追蹤歷史每一次比較——當下看完、能截圖跟主管交代就夠。
- 成本試算不用精確到錢——用「相對代價」讓我比較設定就好,我自己會換算。
- 我不需要它幫我「自動選最佳設定並套用」——明確不要(見痛點)。

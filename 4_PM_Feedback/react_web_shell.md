## 完成判準

AC2、AC3、AC6 須以真實權重和可見 UI 通過；AC1、AC4、AC5 可先由 deterministic 單元／API 測試覆蓋。AC1–AC5 已有本機證據；固定 DINOv2-small 的直接 worker 路徑亦已在 Windows ARM64 通過。AC6 已有 NativeApp managed package、test-grant API 與真 DINOv2 操作的局部證據，但該旅程使用 headless Chromium，NativeApp desktop window 和 OS picker 未驗；`LV-WEB-01-IC-01` 及 M24 仍不能標為完成。任何 `skip`、fake backend、截圖-only、HTTP-only 或模型健康檢查均不得將此 case 標為完成。

## 既有操作旅程與 React case inventory

本表依 2026-11-01 LV 工具列、scripts/app.py 的 UI 分流、使用指南、已存在的 UI／E2E 測試與本機來源 checkout 的誤逮案件規格盤點，共整理 45 個可驗收 journey。每列是一個可完整操作與回讀的 journey；控制項數量不等於 use case 數量。

Legacy 測試只作為 Streamlit 行為錨點，不算 React 通過證據。React case 必須用固定輸入、固定模型、可見 UI 操作重跑；檢查顯示結果、領域數值、檔案輸出、跨工具 handoff、資料夾副作用及重開後狀態。LV-WEB-01-IC-01/02 的單模型真 DINOv2-small visible journey 已在原生 Windows ARM64 CPython 3.14.3／CPU PyTorch 2.12.0 通過（207.65 秒）；多模型真實數值 parity 仍只有 AMD64 證據。IC-01 的 NativeApp managed package/test-grant/headless Chromium journey 只具局部證據；NativeApp desktop window、OS picker、managed package 的原生 ARM64 與完整 parity 仍待驗。LV-WEB-02 的 IMG-01 與 OBJ-01 都有 pinned real DINOv2-small 可見 React journey，並核對 Streamlit 漂移和 PCA 數值；兩者均已在原生 Windows ARM64 通過（IMG-01：218.07 秒；OBJ-01：45.44 秒）。這些是本機 headless Chromium 的 App UI 證據；NativeApp picker/package 與 managed-host 比較仍待驗。標成「本機來源」的文件／測試存在於原 LV 使用者工作樹，但尚未併入此隔離分支，不得當成此分支的 CI 證據。

**Cross-repository React journey follow-up (2026-11-02):** `test_lv_web_10_send_readback_cross_repo_react_browser_journey` covers both a normal curation handoff and a duplicate-pair `verify` handoff. Both passed locally on Windows ARM64 CPython 3.14.3 (`2 passed`, 103.96 s) and in [Windows GitHub Actions run 41441317593](https://github.com/hctsaik/LV/actions/runs/41441317593) (`2 passed`, 27.30 s). The duplicate case scans a cross-split pair, displays its pair metadata in ANnoTation React, records `keep` / `drop` image classifications in the LV-compatible `answers.csv`, restarts ANnoTation and reads both classifications back, then restarts LV and verifies two SHA-matched label changes, audit entries, a round-ledger readback, and unchanged source bytes. This exposed and fixed LV's PNG handoff re-encoding, which had changed the copied bytes while retaining the source SHA name. An intermediate run, [41440093292](https://github.com/hctsaik/LV/actions/runs/41440093292), timed out locating the exact-text `資料集` button; the test now uses a regular-expression accessible-name locator, and both cases pass on retry. Earlier ARM64 attempts had one unexplained second-worker startup exit; the latest two-case run did not reproduce it. Real-model parity and NativeApp packaging remain unverified.

### Case 完成與證據規則

每個 React case 都要有固定 fixture 內容 hash、model/profile/weight 身分、同樣的操作序列及可比較輸出。輸出至少核對畫面內容與選取身分；有數值時核對領域指標與事先定義的容差；有下載時核對檔案內容；有保存時停止 worker 並以新 PID 讀回；最後比對來源資料夾前後 hash。缺檔、空資料、模型不可用及取消依原行為逐列覆蓋。

只有上表裡的旅程都有對應 React case、legacy 對照與可見 UI receipt 後，才能報告 parity。舊 Streamlit 測試、HTTP status、health check、單張截圖或 mock model 都不構成該旅程的 React 通過證據。2026-11-02 managed package 的 DINO test-grant journey 是真模型與 API/UI 流程證據，但使用 headless Chromium，不能代替 NativeApp desktop window 或 OS picker 驗收。隱藏路由、缺少固定 fixture 或只有本機未提交的 legacy 測試列為待釐清，不推定通過。

# LV 誤逮調查整體產品檢視與修訂

日期：2026-09-06。狀態：產品設計與待實作驗收範圍，不是已完成功能清單。

## 為何重新檢視

先前設計從 adapter、Grad-CAM、證據契約出發，未逐步走完使用者的輸入、判讀、修正和交付，所以漏了模型上傳。補一個 uploader 並不能解決同樣存在於資料、評估、選框與回覆上的問題。此次主 agent 與架構、YOLO、案件證據三個 agent 重新檢查實際介面與完整操作旅程，將驗收單位由「模組可執行」改為「使用者能完成工作」。

## 產品主線

工程師的目標是處理一件報案，交付有依據、範圍清楚的回覆，並把值得處理的同類案例帶入人工覆核與改善驗證。模型上傳和 Grad-CAM 是達成目標的必要工具。

提供兩個入口，匯入同一條工作流程：

- **我收到報案**：先上傳圖片／截圖與描述，可以還沒有模型；之後補入或選已有模型。
- **我要先檢查模型**：上傳模型、試跑圖片，試跑結果可直接建立案件，無須重傳或重算。

主線為「收到報案 → 核對現場判定 → 選框並查證 → 整理回覆 → 同類樣本覆核 → 改善驗收」。案件摘要顯示已知資訊、缺項與下一個可執行動作；不要求工程師自行理解七個技術功能區的依賴順序。

## 普通操作的具體規則

### 1. 輸入與資料準備

圖片、模型、參考資料、評估集均有瀏覽器上傳或既有資源選擇；原型完成不能以開發者預先放在伺服器的路徑代替此驗收。大檔案限制在上傳前顯示，伺服器路徑清楚標「LV 主機」。多人／共用主機不需首版建立完整企業權限系統，但不能把其他專案的資料自動混入對照或匯出。

一次匯入先預覽數量、縮圖、來源種類、檔案配對、class map、錯誤與重複。相同檔名但不同路徑不能自動混配；同內容重匯可重用資產，是否新增案件由使用者選擇。ZIP 若採用，須限制解壓大小／檔數及防止路徑越界。

五欄 YOLO 標註不視為有 confidence 的模型預測；零位元／空白的預測檔需由匯入角色與成功配對確認為「已提供、零框」，不能與沒有檔案混同。現場紀錄未帶 LV hash、版本或時間可以保存為部分證據，不能要求工程師造出 contract_id 才開始。

### 2. 一張圖的選框與修正

預測框、人工爭議 ROI、人工真值使用不同樣式與來源標籤。點框選的是具體模型 run 的 detection；框選可疑區域不是捏造 detector 輸出。相鄰框、縮放、同圖兩個不同裁決都要可操作。

變更 UI 顯示門檻不改寫原推論門檻；被隱藏的已選框顯示提示，不偷偷換選其他框。真正調部署門檻建立新設定／run。重播沒有當時框時，保留報案框與本次無框結果，預設下一步是核對模型／前處理／現場紀錄，不產生誤導性 Grad-CAM。

### 3. 分析是幫助判斷，不是更多圖表

首屏回答：正在解釋哪個模型版本、哪張圖、哪個框、哪個分數；與當時結果是否相符；目前證據能說什麼／不能說什麼。可疑區域可點選去看實際修改圖與對照結果，逐步展開方法細節。

CAM 相似或顏色更紅不能自動當成 confidence 更高、模型更差或根因一致；跨模型／層／方法比較保留各自數值尺度與正規化。支持與反駁證據可以同時存在，最終回覆不自動省略反例。

模型分數、NMS／門檻等支援的後處理、現場最終報警分成不同階段記錄。僅重現其中一段就只標那一段。已知 ROI／尺寸等現場規則可保存原記錄與可實作範圍；未知 PLC／集成規則列為缺項。本版不建立任意 PLC 或規則程式執行器。

### 4. 可交付的回覆

從選取的 evidence 形成可編輯草稿：報案情況、目前確認事實、尚待確認、附圖、建議下一步。範例：「原圖在 v3 模型重播出現同一位置的刮傷框；配套模型歸因顯示反光區域有正向貢獻；遮擋測試尚不足以確認根因。建議補同角度正常樣本。」只有真實存在的證據才帶入對應句子，沒有結果就省略／標待補。

可直接複製文字，或下載含圖、可離線開啟的 HTML。主回覆預設不暴露伺服器絕對路徑與全量 JSON；工程 evidence ZIP 另行下載。下載前看得到選取的圖片、模型名稱與說明，不自動發送到外部。人工修改、已回覆與後續更新形成版本，原因仍可保持未知。

### 5. 日常管理與工作恢復

案件列表有搜尋、部署／狀態篩選與最近操作；摘要保留模型、選中影像／框與下一步。多圖案件逐圖保存覆核／分析狀態，批次處理先顯示範圍與張數，部分失敗可以只重試失敗項。

工作狀態為 queued/running/succeeded/failed/cancelled/interrupted；refresh／切頁不重送。重啟後殘留 running 成為 interrupted，可新 attempt 重試；完整舊結果不因重試消失。狀態描述工作階段與耗時，不捏造 ETA。資料／權重缺失可重新附入相同 hash；未知版本環境明示。

模型可改顯示名称、封存和恢复；被案件引用的版本／權重保留，刪除只限未引用草稿並給出確認內容。工作區備份／搬移使用可重建相對資產引用與完整性檢查；模型權重是否包含須在備份清單明示。這是本機工作區維護，不擴張成跨組織同步服務。

## 防止再次漏項的交付方式

每個功能的規格必須同時有：使用者手上有什麼、第一步如何做、成功看見什麼、缺資料怎麼走、選錯如何修正、失敗如何恢復、結果如何交付與再次使用。將 U 編號連結到開發任務與驗收記錄。

保留原技術 gates，但不再以「有 route／API／測試 fixture」等同工程師可以完成工作。原始 adapter、Grad-CAM 與上傳任務未因此移出範圍；新增的是讓整體可用所必需的流程。企業權限、任意 YOLO 變種、PLC 執行器、自動重訓／部署仍不納入，避免用無限新功能取代當前查案需求。

正式規格與任务：[add-yolo-gradcam-case-diagnostics](../openspec/changes/add-yolo-gradcam-case-diagnostics/design.md)。

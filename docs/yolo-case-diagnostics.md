# 外部模型誤逮調查

LV 現在可由案件或模型開始。先在「誤逮案件 → 我的模型」上傳原本使用的 `.pt` 或 `.onnx`，按「檢查模型」，核對類別、輸入大小、縮放、分數門檻與現場版本後保存。模型檔在工作區持久保存，同內容重用資產，設定修改建立新版本。案件保留當次模型快照。

模型庫可上傳一張圖片試跑，直接用結果建立案件；已有案件也可選保存的模型推論原圖，不需要先手填預測框。點圖片上的預測框或從清單選框，再按「解釋這個框」。人工圈區與實際模型預測分開記錄；推論零框仍保留為有效結果，不會製造 Grad-CAM 目標。框或類別修正會撤銷舊覆核適用性，舊證據仍保留供核對。

## 支援範圍與安裝

先安装專案基礎與 `requirements-external-models.txt`，再於相同環境執行：

```powershell
.venv/Scripts/python.exe -m pip install --no-deps -r requirements-yolo-attribution.txt
```

| 格式 | 支援內容 | 邊界 |
|---|---|---|
| 原版 YOLOv5 `.pt` | `yolov5==7.0.14` Detect，objectness × class 分數，另可選 class-only | 不是 YOLOv5u；自訂 head 不接受 |
| YOLOv8 `.pt` | `ultralytics==8.3.203` Detect，原始候選 class 分數 | 不支援 segmentation、pose、OBB 或任意自訂模組 |
| YOLO11 `.pt` | 同一固定 Ultralytics 版本，獨立 Detect adapter 測試 | 不因名稱含 YOLO 就當成相容 |
| YOLO12 `.pt` | 獨立 `ultralytics==8.4.142` 環境，檢查實際 Detect head | 模型家族名稱不能取代架構檢查 |
| YOLO26 `.pt` | 同一現代版環境，分別處理 one-to-many 與 one-to-one 候選 | 固定原始候選與類別；不把排序後的框列號當作原始候選 |
| ONNX | 單張四維圖片輸入；支援明確配置的分類／xyxy／YOLO 輸出 | 可重播、對照實驗；ONNX 本身不提供此處的反向梯度 |

只載入自己信任的模型。PyTorch checkpoint 可以包含 Python 序列化物件；工作子程序提供取消與資源限制，並非惡意程式安全沙箱。LV 不執行使用者提供的 loader 或下載任意 hub 程式。若現場模型不同於固定環境，檢查會明示失敗，案件仍可保存。

ONNX 可之後補上配套 PT；兩者各自保存輸入與輸出設定。使用新版本重新推論案件後，才以新快照分析。跨後端先比對同張完整輸出，類別、框、分數與唯一對應都成立才能接歸因。這是逐圖對應驗證，不等於整個資料分布或歷史部署已驗證。

新版模型使用獨立環境，不升級原本的 `.venv`：

```powershell
.venv/Scripts/python.exe scripts/setup_model_runtime.py
```

上傳模型時選擇相應執行版本，檢查結果會記錄實際版本與 head 路徑。Ultralytics 8.4.142 的 `nms` 介面與舊版不同；可用路徑以權重與匯出設定檢查結果為準，不假定所有 YOLO26 都採相同預設。跨版本模型評估各自在自己的環境執行。

one-to-many 使用 LV 已確認的解碼與 NMS 設定；one-to-one 保留該 head 的輸出候選，再套用 LV 分數門檻與顯示數量。前向數值吻合驗證不代表涵蓋任意 `YOLO.predict` 的全部後處理選項，現場部署仍須以實際設定與歷史紀錄核對。

## 證據如何解讀

正向 Grad-CAM 顯示對指定框分數的正向貢獻；正負診斷分開命名，藍色不是「另一個類別」。熱圖相對強度不能跨圖片直接當 confidence 比較。使用完整原圖推論；畫出的框是所選目標，並不默默裁切模型輸入。

模型診斷顯示實際輸入、熱圖、模型版本、方法與目標。透明度只重新繪圖，不重算梯度。遮擋檢查追蹤原始候選的固定分數，並另外列出修改圖中的重新匹配框。新版協定把相同形狀與面積的熱區遮罩平移到控制位置，禁止裁切或環繞；與原熱區重疊不得超過 10%。固定值填補與模糊填補使用相同遮罩。最多搜尋 512 個位置，找不到足夠控制時明示不可判讀，不以散點控制代替。不同填補／比例的方向不一致時標示不穩定。舊協定結果保留，但不自動當成新版驗證。

沒有梯度、沒有正向值或無定位 mask，都有明確狀態，不補造熱點。可選權重隨機化檢查與對齊原圖 mask；這些檢查不直接判定根因。

原模型輸出、LV 支援的解碼／NMS／門檻與現場機台最終報警是不同階段。站點名稱和後續規則可保存為現場描述；未知或未驗證的機台規則不會變成「完整判定重現」。CSV／JSON／YOLO 現場紀錄沒有 LV hash 也可匯入，但缺少的版本、時間與身分不能由 LV 猜補。

## 回覆與改善

「資料庫」上傳多張圖片或 ZIP，預覽配對、類別、座標與紀錄角色。空預測、未提供預測與格式錯誤各自顯示。同名但不同路徑不猜配；一張圖的 GT 與預測可分批保存。參考資料集直接在「找對照」選用，不需要伺服器路徑。LV 的 DINO 外觀對照仍屬輔助證據。

熱圖可保存為案件證據，從該區域找對照時保留來源連結。候選仍須逐區域人工覆核，匯出訓練前仍要確認整張原圖標註完整。前後模型評估使用保存的模型與資料集，透過表單確認真值、群組與用途；獨立集重疊檢查、支持數及漏檢門檻保留。

改善評估預設使用「逐張看圖確認」：選擇圖片，檢視整張圖片，再填入真值、覆核者、群組與完整標註確認。「常用覆核者」只方便預填姓名，不會自動確認圖片。按「保存本張確認」或「保存並看下一張」才會提交該張資料，完成後再按「確認並建立評估清單」。未保存的表單內容不會加入清單；保存後若修改真值或撤回人工確認，先前清單就需要重新建立。也可切到「表格編輯」批次調整，兩種方式共用同一份確認資料。正常區域或空標註仍不能代替整張圖片的人工確認。

「覆核批次」的含圖片 ZIP 另附 `provenance.json`，接收者可查看區域、來源與覆核快照，並沿選樣引用追到搜尋和模型歸因紀錄。歷史引用不表示修正後的區域仍對應原熱圖，也不代替人工真值。覆核回傳仍只需修改 `review_manifest.json` 的覆核欄位；保留區域身分與來源指紋。圖片與證據資料不需要接收者知道伺服器路徑。

「說明與回覆」提供可編輯事實草稿、支持／反駁／待查關係、附圖與選取熱圖預覽、可複製文字及離線 HTML。工程 JSON／完整熱圖證據包另行下載。舊區域被修正後，相關主張標示待重新核對；回覆過不代表原因已確認。LV 不自動發送回覆或部署模型。

案件可選擇要回答類別分數、框位置、後處理或機台報警。自動摘要列出可核對觀察、引用、缺少證據與下一步；人工稿只在明確重新產生時更新。修改圖是否保留目標外觀由工程師另外確認，確認紀錄綁定全部修改圖指紋；圖片或目標改變後不能沿用舊確認。CAM 不會自動把亮區命名為反光、刮痕或已確認誤逮原因。

跨樣本核對需記錄已覆核角色與群組。目標數、唯一原圖數、人工宣告的群組數分開計算；同張圖多框不增加獨立圖片支持，不同模型／head／實驗協定不混合統計。群組是人工宣告，仍須按產線、批次與採樣方法核對獨立性。

## 工作恢復與備份

「工作紀錄」查看進度、取消、重試或重新把已完成結果加入案件。計算成功與案件發布分開記錄；其他分頁修改了區域時，舊結果保留但不覆寫新狀態。批次可只重試失敗目標。服務重啟後殘留執行狀態列為中斷，不假裝完成。

兩個分頁同時編輯案件時，過期分頁會保留草稿並拒絕儲存。按「開啟最新版本（保留此頁草稿）」後，可對照目前已儲存的報案資訊，再整理並保存自己的修改。本頁完成的分析會正常加入案件，不需要每次手動重新載入。

案件圖片遺失或內容損壞時，「案件與區域」提供「補回原始檔案」。檔案指紋和尺寸吻合才修復，保留案件、框選、覆核與證據身分；不同圖片應透過「補入原圖／其他來源」新增來源。

「我的模型 → 工作區備份與還原」提供可攜 ZIP。備份清楚列出是否包含模型權重；還原驗證完整性後建立獨立工作區，不覆蓋原工作區。無權重備份保留原模型身分，補回相同檔案即可恢復。模型封存保留歷史引用。

## 工時測量

每案「調查工時」分開記錄首次設定、實際操作、等待運算、重複輸入、選錯框重作與證據不足退回次數。原流程與 LV 流程以研究、配對、案例群組、調查者配對，保留執行順序，並由另一位覆核者記錄錯誤與缺乏證據的原因陳述。只有完成且資料齊全的唯一配對列入操作時間差，品質變差仍一起顯示；未配對、重複、自己覆核或舊紀錄不計入。未交錯先後會提示案例熟悉效應。這些是已測案例的差異，不代表未測量使用者的節省比例。

原有 DINO inspector／Model Diagnostics 繼續使用 V1 語意及 224／336／448 路徑。外部 YOLO 由同一 Diagnostics 入口分派，先解析案件身分，不要求準備 DINO head。

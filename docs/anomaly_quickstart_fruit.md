# 瑕疵偵測快速上手（以 fruit 水果資料集為例）

> **一句話**:用一批**純新鮮**水果當「正常參考」建模 → 對**含腐壞**的水果資料夾套用 → 把最可疑的挑出來匯出。
> 三步 wizard,以蘋果為例約 1 分鐘跑完,預期 **AUROC = 1.0**(新鮮 vs 腐壞完全分開)。

本文針對第 8 個工具「🔧 瑕疵偵測(Anomaly Detection)」。資料集已備好在 `C:\code\dataset\fruit`
(該資料夾另附一份 `fruit_anomaly_使用教學.html`;本文是 repo 內維護的 markdown 版,內容對齊目前 app 的 UI)。

---

## 0. 前置

- App 已啟動(本機 **http://localhost:8501**)。左側工具選單選 **「瑕疵偵測」**。
- 資料集 `C:\code\dataset\fruit` 為標準 YOLO(`images/` + `labels/` 並列),3 種水果 × 新鮮/腐壞,共 180 張、512×512、每圖一顆水果特寫。
- **App 不會寫你的資料集**:所有快取(裁切 / embedding / 縮圖 / 模型)一律進 `.lv_cache/`。

### fruit 資料集的三種現成佈局

| 佈局 | 路徑 | 用途 |
|---|---|---|
| **逐水果(建議)** | `…\fruit\per_fruit\<apple\|banana\|orange>\<fresh\|rotten>` | 一次做一種水果,**最乾淨、AUROC 最高** |
| 快速一把抓 | `…\fruit\anomaly_split\fresh`(30 張)/ `…\anomaly_split\rotten`(150 張) | 混 3 水果,僅示範用(會稀釋) |
| 忠實 YOLO split | `…\fruit\train`(144)/ `…\fruit\valid`(36) | 一般訓練/驗證切分 |

> **為什麼「逐水果 >> 混水果」**:把不同水果丟進同一個 Normal Bank 會互相稀釋(蘋果的正常分布去稀釋橘子),
> 實測 AUROC 會從 **1.0 掉到 ~0.78**。**手冊全程建議:一次只對一種水果建一個模型。**

---

## 1. 三十秒結論(以蘋果為例)

**側欄設定**(只影響下次①建模):

| 側欄項目 | 選 | 為什麼 |
|---|---|---|
| DINOv2 模型 | `dinov2_vits14`(預設) | 自然影像 vits14 已達 1.0,不必用較重的 vitb14 |
| 流程 | `1-stage(直接整批)` | 純驗證、已知是正常/腐壞,不需抽樣確認 |
| **分數依據** | **`物件級(快,粗)`** ← 預設是 patch,**請改成 object** | 腐壞=整顆大尺度變色,物件級就 1.0;又快又穩,且**不踩 patch 的少樣本陷阱** |

**三步**:

1. **① 建模**:訓練/參考資料夾填 `C:\code\dataset\fruit\per_fruit\apple\fresh` → label 語義選 **「物件類別」** → 按 **▶ (1) 建立模型**。
2. **② 套用**:目標資料夾填 `C:\code\dataset\fruit\per_fruit\apple\rotten` → 按 **▶ (2) 套用偵測**。
3. **③ 挑樣**:點 **「純 novelty」** 格 → 大圖牆挑最可疑 → **🛒 加入購物車** → ② 分頁 **⬇ 匯出選取原圖 ZIP**。

香蕉、橘子把路徑裡的 `apple` 換成 `banana` / `orange` 即可。

---

## 2. 逐步走查

### 先設側欄

進「瑕疵偵測」後,**左側欄**有 `### 🔧 瑕疵偵測設定(作用於下次①建模)`:

- **DINOv2 模型**:留 `dinov2_vits14`。
- **流程**:選 `1-stage(直接整批)`。
- **分數依據**:**改成 `物件級(快,粗)`**。
  - ⚠️ 預設是 `patch 級(抓細微瑕疵,較準)`。fruit 的腐壞是整顆變色,物件級足夠且更穩;patch 模式留到第 5 節進階再用。
  - 選 object 後,「解析度」選單會消失(那是 patch 專屬)——正常現象。

> 側欄這幾項**只作用於下次①建模**;②③ 一律用模型鎖定的設定,改側欄不會改變已建好的模型。

---

### ① 建模 / 載入模型

步驟列(畫面上方)選 **`① 建模 / 載入模型`**。

1. **(1) 選訓練/參考資料夾**:在「或輸入路徑後 Enter 加入」的輸入框貼上
   `C:\code\dataset\fruit\per_fruit\apple\fresh`,按 Enter。(也可按 **📁 新增資料夾** 用原生對話框選。)
   - **這裡一定要是「純新鮮」**:patch / 物件級建模都把這批當「正常參考」。混入腐壞會污染 Normal Bank。
2. **(2) 你的 YOLO 標籤名稱代表什麼?**:選 **「物件類別(門 / 窗 / 螺絲…)」**。
   - fruit 的類別名是 `fresh_apple` / `rotten_apple` 這種**水果/狀態名稱**,不是「刮傷/裂痕」這種**缺陷類型**。
   - 選「物件類別」→ 只跑離群偵測找異常,**不訓練分類頭**。這是**對的**——選「瑕疵類別」會把物件類別硬當缺陷類訓練(silent-wrong)。
3. 按 **▶ (1) 建立模型**。
   - 成功會出現:`✅ 模型已建立 · dinov2_vits14@224 · object · N 物件 · 語義=物件類別 · 無分類頭 → 切到 ②套用偵測`。
   - 「**無分類頭**」是預期的(物件語義不解鎖 head)。

> (可選)**存模型**:在「(2) 模型暫存目錄」按 **💾 存模型**,之後在別的資料夾按 **📂 載入模型** 就能重用同一個 bank,不必重建。預設存在 `.lv_cache/`,不碰你的資料集。

---

### ② 套用偵測

步驟列選 **`② 套用偵測`**(畫面頂端會顯示 `🔒 用模型鎖定的 dinov2_vits14@224 · object 評分`)。

1. **(1) 選異常目標資料夾**:填 `C:\code\dataset\fruit\per_fruit\apple\rotten`。
2. 按 **▶ (2) 套用偵測**。
   - 找不到 `images/` + `labels/` 會明確報錯;確認路徑無誤即可。
3. 看結果:
   - 概要列:`共 N 個物件 · 判為可疑(bad)M 個 · 門檻 0.xxx`。
   - **左欄散點圖**:點越紅越可疑,灰底=新鮮參考分布;可拖曳框選離群點。
   - **右欄看圖**:`🔥 最可疑物件`,用「異常分數範圍」slider 篩選、selectbox 逐張看大圖。

> **若跳「⚠ 全部被判為可疑 = 門檻無法校準」**:代表目標裡幾乎沒有「正常」可當基準。
> 在散點圖**框選你確定正常的那一團點 → 按「✅ 框選標為正常範例」→ 按「🔁 就地重評」**,用乾淨參考重算門檻(不動模型)。
> 對 `per_fruit\apple\rotten`(全腐壞)這種「目標幾乎全異常」的情境,這是正常會遇到的;框幾顆相對正常的當錨點即可。

---

### ③ 挑樣送人工標

步驟列選 **`③ 挑樣送人工標`**。

- 上方「取樣模式(點一格 → 右下出大圖牆)」是 **2×2 矩陣**:
  - `偏 novelty(稀有/未知更強)`、`弱類定向(分類頭最混淆)`、`三訊號均衡`、`純 novelty`。
  - **fruit(物件語義、無分類頭)時,前三格會反灰顯示「🔒 需分類頭」,只有「純 novelty」可點——這是預期的。**
    那三格的差異全靠分類頭訊號,沒有 head 時與純 novelty 完全等價,所以鎖起來避免假選項。
- 點 **「純 novelty」** → 右下出**大圖牆**(可調「每列張數」2–6、「縮圖高度」120–400)。每張下三行:類別名 / `判定:可疑或正常` / `異常 0.xx`。
- 按 **🛒 把「純 novelty」佇列 N 個加入購物車(送標註)**。
- 回 **② 分頁**,散點圖下方按 **⬇ 匯出選取原圖 ZIP**(檔名 `anomaly_subset.zip`,匯出的是**原圖**不是裁切)。

---

## 3. 預期結果(實測 AUROC,新鮮=正常 vs 腐壞=異常)

| 設定 | 蘋果 | 香蕉 | 橘子 |
|---|---|---|---|
| **物件級,逐水果(本文走法)** | **1.0** | **1.0** | **1.0** |
| patch 級,逐水果,參考 8 張 | 0.844 | 1.0 | 1.0 |
| 混 3 水果(combined) | \~0.78 整體 | — | — |

> 物件級逐水果 = 完美分離,且 few-shot 很穩(5 張參考即 1.0)。這也是建議「一次一種水果、用物件級」的實證依據。

---

## 4. 換水果 / 跨資料夾重用

- **換水果**:把 ① ② 路徑裡的 `apple` 換成 `banana` 或 `orange`,重跑①②③。每種水果各建各的模型。
- **重用模型**:①「💾 存模型」存成一份 → 之後對新資料夾在同路徑「📂 載入模型」→ 直接到②套用,不必重建 bank。

---

## 5. (進階)什麼時候用 patch 級

物件級已能在 fruit 上拿到 1.0,**多數情況不需要 patch**。patch 級的優勢只在「**瑕疵很小、需要 patch 細緻度**」(例如表面細微刮痕),且要**足量純正常參考**才建得出 Normal Bank。

若要試 patch:

- 側欄「分數依據」改 `patch 級`,「解析度」依瑕疵大小選(`224` 16×16 最快 → `560` 40×40 最細最慢)。fruit 大物件 `224` 已足夠。
- patch 模式才會在②看大圖時**疊熱力圖**(紅=最不像正常);物件級只顯示裁切圖。
- **注意參考量**:fruit 每種水果只有 10 張新鮮,屬少量。patch 模式對少參考敏感(見下一節)。

---

## 6. 疑難排解

| 症狀 | 原因 / 解法 |
|---|---|
| 側欄找不到「解析度」 | 只有「分數依據=patch 級」才出現;物件級不需要。 |
| ③ 2×2 有三格反灰「🔒 需分類頭」 | **正常**。物件語義不訓分類頭,只有「純 novelty」有意義。要解鎖須 label 語義=瑕疵類別且每類達 N_min——但 fruit 不該那樣設。 |
| ② 跳「全部被判為可疑」 | 目標裡沒有正常基準。散點框選相對正常的點 → 「✅ 框選標為正常範例」→「🔁 就地重評」。 |
| patch 模式按建模卻**建不出 bank** | 參考太少或太雜。app 會明確報錯:「patch 模式建不出 Normal Bank(參考可能全被標為瑕疵,或無正常物件)。請確認參考資料夾多數為正常,或側欄『分數依據』改用『物件級』。」→ **最穩的解法:改回物件級**(5 張就夠,且不踩此陷阱)。 |
| 看大圖沒有熱力圖 | 物件級模式只有裁切圖;要熱力圖請用 patch 模式(且已建出 Normal Bank)。 |
| 換了資料夾,之前框選的標記不見了 | **預期**。換訓練/目標資料夾會清掉對應索引空間的殘留標記,避免舊索引污染新資料夾。 |
| 想確認沒寫到資料集 | 所有產物都在 `.lv_cache/`;`C:\code\dataset\fruit` 不會被寫入。 |

LV 使用指南（VisualLatent）

一句話：先用 Visualize 探索＋診斷，再從樞紐分流到其餘四個工具。 每個工具回答一個不同的問題、對應瑕疵漏逮的不同「桶」。 圖解見 tools_overview.html（五工具樞紐圖＋四桶對應）。

心智模型：探索 → 行動，對應四桶

LV 不是五個各自獨立的功能，而是一條「探索 → 診斷 → 分流 → 處置」的線。 Visualize Embeddings 是樞紐（探索＋單筆診斷＋策展分流），其餘四個是你從樞紐走向的「行動」。

工具 回答的問題 對應四桶
① Visualize Embeddings 這批影像長怎樣？這筆漏逮為何沒抓到？ 樞紐（碰①②③）
② Compare Distributions A/B 兩組影像的整體特徵漂移多大？ 桶② 分布·覆蓋
③ 完整度熱力圖 我這堆內部哪裡缺／假完整？ 桶② 覆蓋不足
④ 組考卷 「什麼算瑕疵」這把尺準不準？ 桶③ 量這把尺
⑤ 灰帶覆核 連人都會吵的邊界樣本怎麼處置？ 桶③ 處置·人機協作

瑕疵漏逮四桶（問題本質，詳見 defect_problem_redefinition.md）：

  • 桶① 物理天花板：訊號沒進資料，補資料無效 →（Visualize 的 🧱桶①佔比 / 體檢卡 S0 閘先攔截）
  • 桶② 覆蓋不足：樣本太少，補了大概率有效 →（完整度熱力圖＋Compare＋Visualize 選樣/相似挖補）
  • 桶③ 邊界帶：連人都會吵，逐筆不可判定 →（組考卷「量」＋灰帶覆核「處置」）
  • 桶④ 迴圈漂移：追「最近被大聲抱怨的東西」→ 非工具能解，屬合約/權力，誠實標記為非工程帳

啟動與前置

完全離線：模型權重只從本機讀取。

pip install -r requirements.txt

# React Web 開發預覽（目前的遷移目標）
cd web
npm ci
npm run build
cd ..
python scripts/react_web_shell.py       # http://127.0.0.1:8765

# 模型權重（不在版控；冪等 provisioning）
python scripts/setup_models.py                # 核心：DINOv2 + Chinese-CLIP
python scripts/setup_models.py --with-compare # legacy CLI 的 FID/LPIPS 權重；目前整圖 Compare 不需要

# 舊版 Streamlit 行為參考（不是 React 交付入口）
streamlit run scripts/app.py                  # 開在 http://localhost:8501

目前 React 可見切片包括 Image Classifier 整圖及 Compare 整圖 A/B；其它既有工具仍依 case inventory 分批遷移。設定 LV_MODELS_DIR 與 LV_CACHE_DIR 可指定本機模型根目錄及 worker 的可寫 cache 位置。

資料夾結構： - Object Detector（YOLO）：<folder>/images/（＋可選 labels/ 為 YOLO .txt）。類別名取 classes.txt。 - Image Classifier：<folder>/類別名/影像.jpg（依類別分子資料夾）。

冷啟動可按主畫面「✨ 用範例資料試跑」零下載體驗（coco8）。

① Visualize Embeddings — 探索＋診斷＋分流（樞紐）

解決什麼問題

把一個或多個圖片資料夾丟進深度模型萃取特徵，降維成可框選的散點圖，讓你「肉眼＋語意」一次看清資料分布。它不只是視覺化：右欄 7 個面板把探索（找相似、以文搜圖）、診斷（離群、標籤分歧、體檢卡根因、桶①佔比）與分流（多樣性選樣、購物車送考卷／灰帶）串成一條龍。整個流程完全離線，且不寫回資料集——只產出清單與報告。

什麼時候用

  • 拿到新資料、想先看分布與異常，再決定怎麼清理或補樣。
  • 懷疑 train/val 有洩漏、重複、標錯，想用一張圖找出可疑群。
  • 模型在某類樣本一直判錯，想釐清「補資料到底有沒有用」（根因 H0–H5）。
  • 想量「物理上根本拍不到的缺陷」佔多少（桶①），避免白補資料。

怎麼操作

1. 載入資料夾（左側 sidebar「① 資料」） — 先選「模式」（切換模式會清空舊結果，但提供「↩ 復原上個模式的結果」後悔藥）： - Object Detector：YOLO 格式，每個資料夾需含 images/（及可選 labels/）。類別名優先序：手動選的 classes.txt ＞ 父目錄 classes.txt ＞「類別來源」expander 手動輸入。 - Image Classifier：依類別分子資料夾，類別自動偵測。

用「📁 新增資料夾」挑路徑，或在文字框貼多行路徑（兩者合併）。

2. 選模型（「② 模型」） — 從 models/ 多選（各算一份 embedding）。選 chinese-clip 會解鎖「相似」面板的以文搜圖。

3. 投影方法（「③ 投影方法」）＋執行 — 勾選 PCA / t-SNE / UMAP（只勾要的可大幅縮短時間）。UMAP 可開「固定 UMAP 參考系」凍結座標讓跨 Run 可比較。按 ▶ Run：縮圖快取 → 更新 manifest（增量）→ 逐模型特徵擷取（快取於 embeddings_<model>/embeddings.npz）→ 降維。

主畫面用 Model / Method / Split 下拉切換視圖，在散點圖框選/套索，右欄即時對應。右欄頂端切換 7 個面板：

  • 選取：框選後縮圖牆；排序（空間順序／離群度／標籤分歧／檔名）；未選取時自動顯示離群前 N（標明「僅供排序，非品質判定」）。含「📝 策展日誌」落盤、可重選、匯出 CSV。
  • 相似：以圖搜圖 kNN，可「↻ 以此為查詢」鏈式續查；chinese-clip 時多以文搜圖（繁簡自動正規化）。
  • 重複：phash（嚴格）或 embedding（語意）去重；勾「僅跨 split」＝ train/val 洩漏候選。並排複核，標明非自動判決。
  • 選樣：farthest-point 多樣性／主動學習，勾「避開匯出清單」只挑離已覆蓋最遠的新樣本。
  • 體檢卡：單張 escape 根因報告（先點一張縮圖/散點）。三訊號 S1 人類一致性（滑桿，來自組考卷）、S2 命中密度、S3 模型不確定度（有 scores.csv 用分數 margin，否則退鄰域標籤熵代理）＋ S0 桶①閘（🟢明顯/🟡疑似/🔴確無/⚪未知），經 diagnose_root_cause 給出 H0–H5 與「補資料有效性」：
  • H0 物理天花板（S0=確無）→ 補資料無效，要動成像鏈。
  • H1 覆蓋缺口 → 補這格大概率有效（訊號未確認為明顯時會出 ⚠ caveat 提醒先量訊號）。
  • H2 定義歧義 / H3 標籤雜訊 / H4 容量限制 / H5 OOD → 各有對應行動。 附最近鄰縮圖牆，可「⬇ 匯出體檢卡 HTML」。
  • 桶①佔比：逐影像類型統計 🔴確無(桶①)/🟡疑似/🟢明顯/⚪未知＋整體佔比。按「🎯 從目前資料重新校正門檻」就地量 SNR 校準（全域＋逐類型），再「📊 計算桶①佔比」。標明「確無是桶①下界，校準前偏估」。
  • 匯出清單：跨工具累積的「策展購物車」（帶來源標籤、跨 Run 保留）。可篩選/加註理由、分流到「📝 出考卷」「🌫 送灰帶覆核」、匯出 CSV/ZIP。

輸入 / 輸出

  • 輸入：圖片資料夾；可選 classes.txt；可選 scores.csv（filename,score[,threshold]）→ 體檢卡 S3 的 N4 閘來源。
  • 輸出：縮圖/embedding 快取、manifest（含 sha256）、桶①校準 signal_gate.json、策展日誌與各面板 CSV、購物車 ZIP、體檢卡 HTML。

注意事項與限制

  • 離群度／標籤分歧／命中密度都是幾何/鄰域統計，不是品質判定或誤標判決，只供排序與線索。
  • 重複掃描僅供人工複核，非自動判決。
  • 體檢卡歸因只涵蓋 N2（覆蓋）/N3（標籤分歧）＋可選 N4（分數）；N0 影像品質、N1 定義仲裁需人工，訊號不足會回「需人工覆核」。
  • 桶①門檻是教科書起點，必須就地用真實 escape 校準才可信；無 ROI 一律判「未知」不臆測。
  • UMAP 不保密度：投影只供肉眼定位，不可當密度量尺。

對應四桶

  • 桶①：「桶①佔比」面板逐類型量、體檢卡 S0/H0 對單張下判（唯一能直接量到的一桶，且只到下界）。
  • 桶②：「選樣」做主動學習挑該補的、「相似/以文搜圖」針對缺口挖補（對應體檢卡 H1）。
  • 桶③：找出可疑邊界樣本→體檢卡判 H2/H3→從「匯出清單」分流送組考卷（量一致性）或灰帶覆核（雙簽裁決）。

② Compare Distributions — A/B 影像群組差異

解決什麼問題

比較兩組影像的 LV feature embedding，回答「A 與 B 的整體特徵中心差多少」。整張影像模式會回報 A/B embedding 形心的餘弦漂移；投影圖用來找出可以回看的樣本位置。投影上的距離只供視覺探索，不取代漂移分數。

什麼時候用

  • 比較 train 與 validation、資料版本更新前後、或真實影像與合成影像。
  • 不需要 YOLO labels、只想檢查整體影像特徵時使用「整張影像」模式。
  • 需要找出哪個 YOLO 類別變化時，選「物件級・按類別」模式。

與「完整度熱力圖」不同，Compare 對照 A 與 B；完整度熱力圖分析單一資料集內部哪些位置樣本不足。

怎麼操作

  1. 在 Folder A 與 Folder B 各加入一個或多個資料夾。同一側的圖片會合併成一組；用各列的 ✕ 可移除資料夾。
  2. 選一個本機 Model，再選 整張影像（不分類別） 或 物件級・按類別（YOLO）。
  3. 按 ▶ Run。若選物件級，請提供含 images/ 與 labels/ 的 YOLO 資料集；系統會自動尋找兩側共用的物件設定。
  4. 看整體漂移分數與 A/B 張數。切換 投影方法（PCA、t-SNE、UMAP、LDA、監督 UMAP）及 2D／3D，觀察 A/B 點群。
  5. 整圖模式可在 2D 散點點選或框選樣本；下方左右畫廊會顯示選取圖片。沒有選取時顯示兩側各前 12 張。物件級模式按類別查看漂移表與縮圖。

整體漂移怎麼算

對 A、B 各自的影像 embedding 取平均並正規化，再算 max(0, 1 - cosine_similarity(mean_A, mean_B))，結果四捨五入到小數第 4 位。分數越大代表兩組的平均特徵方向越不同。若兩側有重複圖片或壞檔，畫面會顯示警告。

輸入 / 輸出

  • 輸入：Folder A、Folder B 各一或多個資料夾，以及一個 LV feature model。若資料夾內沒有直接圖片，整圖模式會遞迴搜尋子資料夾。
  • 整圖輸出：整體漂移、可切換的 A/B 投影、選取狀態與兩側縮圖畫廊。
  • 物件級輸出：共同類別漂移表、只出現在單側的類別提示、投影與兩側物件縮圖。

注意事項與遷移狀態

  • PCA／t-SNE／UMAP／監督投影的座標用於視覺檢視；不要以投影距離當成整體漂移分數。
  • FID、KID、LPIPS、SSIM、PSNR、IS 與 Coverage Gap 不在目前 Streamlit Compare 畫面中。test_s05_compare_distributions_metrics 已 skip，屬於舊流程，不能作現行 React 驗收基準。
  • React case LV-WEB-02-IMG-01 目前實作整圖 A/B；deterministic UI/API 測試只證明接線與讀回，不代表真實模型數值 parity。物件級流程、NativeApp folder grant 與完整 3D KMeans 區塊操作仍待遷移驗證。

③ 完整度熱力圖 — 單一資料集內部完整度

解決什麼問題

回答「我這一堆資料，內部哪些格子缺、哪些是『假完整』（量夠但都是近重複）」。把單一資料集切成可解讀的小棋盤格，每格同時看量（n vs 目標 t）與embedding 多樣性 d，滾成一個 Coverage Health 數字＋護欄（Gini、假完整比例）。服務桶② 覆蓋，視角是「單一堆內部」。

操作流程

側欄：貼含類別子資料夾的影像資料夾 → 選模型 → ▶ 開始分析。跑完最上方切換屬性棋盤 vs 嵌入覆蓋圖。

子檢視 A：屬性棋盤

依可解讀屬性軸切格（不用 UMAP 切格，那會扭曲密度）。熱力圖上方可即時調整免重跑： - 橫看(X)/直看(Y)：類別、資料集(split)，或自動屬性 亮度/對比/銳利度/長寬比。 - 連續特徵分幾檔、每格至少幾張(t_abs)、近重複警戒(d*：寬鬆0.45/標準0.6/嚴格0.75)。

五態（優先序高→低）：🟥缺 n<0.5t｜🟧偏缺 0.5t≤n<t｜🟩健康 n≥t且d≥d*｜🟪假完整 n≥t但d<d*（近重複充數）｜🟦過多 n≥1.5t且d≥d*。低多樣性優先於過多（量夠但近重複先判假完整，因為該去重不是再補）。 指標卡：Coverage Health（達標格佔比，假完整打0.7折）、缺格數、Gini 不均度、假完整比例。 真實分佈校正（🎚）：每格設頻率先驗 高(×2)/中(×1)/低(×0.4)/不適用，避免稀有格被誤判缺。 右欄：缺格清單、點格看格內影像；缺格可 🔎 撈候選補此格（mine_candidates 以格心做以圖搜圖）。

子檢視 B：嵌入覆蓋圖

不切格，直接在特徵空間真實形狀裡找稀疏盲區（稀疏度一律高維算，投影只供畫）。稀疏度 ≥ 自參照 P80 即盲區候選。偵測資料集可切「物件級」（裁 bbox 各自算）。 根因 H1–H5 誠實閘（🧭，diagnose_sparse_points）：用 S1 人類一致性、S2 密度、S3 標籤熵（＋S0 訊號）交叉定位，統計「補資料有效(H1/H5)」與「桶①物理天花板(H0)」各幾點。 參照分佈 B 模式：投影一個外部資料夾後，可當「採礦池」（rank_gap_fillers 挑最補洞的）或「參照分佈」（reference_coverage 量「覆蓋參照 B X%」與未覆蓋點）——這是覆蓋圖第一次有外部真值（自我參照稀疏看不出「全資料集都缺的類型」）。

注意事項與限制

  • 稀疏 = 自我參照、未校正真實分佈：全資料集都缺的類型不會顯示為稀疏；要量「相對真實分佈缺多少」須用參照分佈 B 模式。
  • 假完整看多樣性 d 不是量；屬性棋盤目標 t 預設均勻假設，需頻率先驗校正才誠實。
  • 稀疏 ≠ 模型一定弱：是否真該補由 H1–H5 閘判（只有 H1 與新樣態 H5 補才有效）。
  • 對應四桶：桶② 覆蓋；根因閘會把 H0 點歸給桶①。

④ 組考卷 — 量「什麼算瑕疵」這把尺準不準

解決什麼問題

「同一張圖、同一定義，不同人（甚至同一人不同時間）給不同標籤」——把爭議樣本變成盲測考卷，量兩件事：自我一致性（intra-rater）＝同一人換皮重測答不答得一致；跨人一致性（inter-rater）＝多人是否彼此同意。它是量測，不改任何資料。

什麼時候用

  • 上線新標註者或定期校準時，先量對既有案例穩不穩。
  • 懷疑某類「人說不清」（概念歧義）時，用考卷分數當體檢卡的 S1 輸入。
  • 從別工具收到一批可疑樣本，想先盲標量一致性而非急著改標。

怎麼操作

  1. 載入資料：貼含類別子資料夾的影像資料夾、選模型（只用來算 kNN 標籤分歧挑爭議樣本）、「載入資料」（需 ≥2 類別）。
  2. 出題：設單卷題數（預設 16），「產生考卷」。依分歧度排序後混入四種題型：爭議題（分歧最高，主體）｜對照題 distractor（約25%，明確且不同類，分開「判斷漂移」與「題本身難」）｜換皮重測 repeat（約20%，自我一致性配對）｜golden 定錨（約12%，最清楚樣本當標準）。出題後打亂、切斷原題與重測的相鄰。
  3. 盲測換皮只允許幾何變換：白名單 rot90/180/270、fliplr、flipud、crop90；對比/亮度/銳化等光度變換直接拋例外（會擾動灰帶判定）。
  4. 逐題作答：不顯示原標籤，按類別鈕作答。
  5. 單卷成績：自我一致率、vs golden 一致率、達標與否；匯出作答 CSV（qid,answer）。
  6. 多人一致性：每人各自跑同卷、各自匯出 CSV，到「👥 多人一致性」上傳 ≥2 份，取共同題算 Fleiss kappa。

統計量與及格線

指標 及格線 量什麼
自我一致率 self-consistency ≥ 0.90 換皮重測配對答一致比例（intra-rater）
vs golden 一致 ≥ 0.85 golden+distractor 與標準答案一致率
Fleiss kappa ≥ 0.75 多人在共同題上的一致性

（缺答配對跳過；無已答配對 self=0；Fleiss 要求每題評分人數一致且 ≥2。）

注意事項與限制

  • 量的是「對既有案例的判定穩定性與一致性」——不是新型瑕疵檢出率，也不保證 golden 本身正確。
  • 補洞候選帶暫定標籤（1-NN 轉移），不是真值宣稱。
  • kappa 沒有信賴區間，小樣本波動大，須留意共同題數。
  • 這是量測工具，全程不改資料。 要改標到「灰帶覆核」。
  • 對應四桶：桶③ —「量」這把尺（群體層級）。

⑤ 灰帶覆核 — 邊界樣本的人機協作裁決

解決什麼問題

有些樣本天生落在判定邊界（「灰帶」）。若讓人在散點圖隨手改標，裁決沒紀錄、沒第二人把關、無法回溯。灰帶覆核把爭議樣本攔在暫存區，提供「對照明確錨例 → 提議軟標籤 → 雙簽覆核 → 匯出決策」的有紀錄裁決。改標只在這裡做，且不直接寫回資料集。

什麼時候用

  • 標籤分歧（散點探索）已找出可疑點，需對每筆做可稽核處置。標籤分歧與灰帶覆核是「同一條線兩端」——前者探索、後者裁決。
  • 組考卷量出低一致批、或散點/購物車送來的批需逐筆處置。

怎麼操作

  1. 建立覆核佇列：貼資料夾、選模型、設「佇列張數（最爭議前 N）」、「建立覆核佇列」。系統用 compute_label_disagreement 取分歧最高前 N 入列，並為每類選最明確一張當錨例（需 ≥2 類別）。
  2. 疊圖對照錨例：每筆灰帶樣本顯示其 cosine 最近的明確錨例（含距離），幫判斷「離哪個明確例近」。
  3. ① 標註者提議軟標籤：選 soft label、拉信賴度（預設 0.67）、填一句理由（必填）。記 proposer=標註者、狀態 proposed。
  4. ② 品保覆核（雙簽，人員不可重疊）：品保按「覆核通過」標 approved、approver=品保QA，或「退回（重議）」。提議者與核可者是兩個角色，不可同一人包辦。
  5. 匯出決策：通過雙簽的進決策清單，匯出 CSV（path, soft_label, confidence, anchor, reason, proposer, approver, status）。

注意事項與限制

  • 灰帶不直接寫回資料集：確認後匯出決策，由下游流程併入。
  • 改標只在這裡做，不在散點圖隨手改。
  • 錨例與最近鄰是參考訊號，不替代雙簽裁決。
  • 對應四桶：桶③ —「處置」邊界帶（群體/受控流程，非散點上逐筆隨手）。

桶① 訊號強度閘與校正（跨工具的物理可偵測性軸）

三訊號根因（H1–H5）原本沒有「訊號到底在不在像素裡」這個軸，導致物理上看不見的 escape 會被判 H1「補資料有效」——其實補了也沒用。桶①閘（scripts/signal_strength.py）在 H1–H5 前先量缺陷 ROI 對局部背景的 SNR，粗分 🟢明顯/🟡疑似/🔴確無/⚪未知；確無 → 直接判 H0 物理天花板。

門檻要校準才可信（教科書起點只是 starting point）。兩條路：

  • App 內（免命令列）：Visualize → 「桶①佔比」面板 → 「🎯 從目前資料重新校正門檻」。從目前載入資料量 SNR、算全域＋逐影像類型門檻、存入 signal_gate.json（已 gitignore），自動套用。
  • CLI： bash python scripts/calibrate_signal_gate.py --dataset <YOLO資料> --type-from class --write 從既有標註框的 SNR 分佈反推門檻（確無線在分佈下方、明顯線以 Rose=5 為硬上限），--type-from {parent,class,none} 逐類型校正，--write 持久化。

校準後，體檢卡與「桶①佔比」會顯示「該類型門檻（none/obvious、來源）」，匯出的體檢卡 HTML 也帶上。

為什麼要逐類型：實測 NEU-DET 鋼材瑕疵，crazing（細裂紋）SNR 中位數 0.24、scratches（刮痕）2.02，差約 8 倍。單一全域門檻會把真實 crazing 誤判成桶①、又對 scratches 太鬆。請拿你自己的瑕疵資料跑一次校正——COCO/NEU-DET 只是驗證流程的替身。

典型工作流：一筆 escape 來了怎麼走

  1. 進 Visualize（Object Detector 模式），把客戶回報的漏逮影像載入、▶ Run。
  2. 在散點上找到它 → 右欄「體檢卡」看根因：
  3. S0=確無 → H0 物理天花板：補資料無效，標記為桶①，回報需改成像（非工程帳）。
  4. H1 覆蓋缺口：補這格有效 → 用「選樣/相似」挖同型樣本、或到「完整度熱力圖」找該補的格、撈候選 → 補資料重訓。
  5. H2 定義歧義 / 標籤分歧高：別急著塞訓練集 → 從「匯出清單」送「組考卷」量人類一致性；爭議的送「灰帶覆核」雙簽裁決。
  6. 想確認新一批資料分布對不對 → 「Compare Distributions」比新批 vs 舊批 / 真實 vs 生成。
  7. 桶①門檻沒校過 → 先在「桶①佔比」按「重新校正」，再讀佔比與根因。

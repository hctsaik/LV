# 誤逮案件診斷工作台

用途：接收外部模型的疑似誤逮報案，用 LV 找對照、保存逐區域覆核與證據說明，再建立 Active Learning 待覆核批次。外部 ONNX 推論、對照實驗、訓練交接及前後評估已接入，詳見 [外部模型完整流程](external-model-investigation.md)。

## 開始查案

啟動既有 `streamlit run scripts/app.py`，在上方工具列選 **誤逮案件**。

1. 上傳圖片／截圖，或填寫本機圖片路徑。案件名称、報案理由、外部模型版本、門檻與原始輸出可逐步補齊。建立後立即持久保存；後續表單按儲存保留修改。
2. 在 **案件與區域** 指定爭議範圍。座標為相對影像的百分比：左、上、右、下；預設整張。支援多個框，以及 YOLO 六欄 `class cx cy width height confidence` 預測檔匯入（座標 0–1）。匯入框一律待覆核。
3. 每個框分別記錄「待覆核、確認此區域正常、確認有瑕疵、規格有爭議、資訊不足」，並填寫覆核者及判斷依據。局部正常不代表整張圖正常。
4. 可在同案補入原圖或其他來源，保留原本截圖與內容身分。截圖上的文字、框線和縮放會影響比對，不能當成外部模型原始輸入。

## 找對照

在 **找對照** 選擇爭議區域，指定正常及真瑕疵資料夾；任一可留空，也可包含已覆核歷史案件。按 **找對照案例** 才會載入本機 DINOv2 並計算，不會自動訓練 LV 分類 head。

- 整張對照圖：適合參考資料已裁成物件圖片。
- 相同比例位置：適合影像已對齊；候選使用與報案相同的 normalized ROI，不能假定不同照片已對齊。
- 正常／瑕疵資料夾是使用者提供的類別範圍，不會自動成為人工裁決。相同內容出現在兩類時會提示衝突。
- 顯示的是 cosine 相似度，不是機率，也不是外部模型信心。
- 每來源預設上限 300 圖／區域，每欄預設 6 筆。超過上限、跳過壞檔、沒有對照都會明示；沒有找到不能推論訓練資料必然缺漏。
- 歷史對照保留案件、區域覆核和模型版本；不會繼承歷史根因。
- 搜尋紀錄保存來源 digest、模型 checkpoint digest、裁切方式、搜尋範圍與引用 ID。重新查看時來源檔變更會提示重新搜尋。

在對照卡按 **加入待覆核**，建立去重候選。正常對照、真瑕疵、歷史案件都可以加入，但新候選仍須覆核。

## 說明與回覆

在 **說明與回覆** 新增或編輯「確認事實、待驗證假設、下一步」，每段選取至少一筆案件證據。證據詳細內容可查閱原始輸出、區域、人員覆核或 LV 對照來源；歷史覆核紀錄不會被抹除，請核對時間與適用區域。

說明是工程師撰寫與覆核的內容，不是系統自動確診。LV 外觀對照只提供輔助線索。外部推論、歷史 parity、對照實驗和前後評估均以各筆證據的模型／來源／資料集範圍呈現，不自動確認因果根因。**已回覆使用者** 與上述狀態分開。

可下載 Markdown 案件說明及完整 JSON 快照。Markdown 引用以 evidence ID 對應報告末尾的證據紀錄。

## 覆核批次與 Active Learning

在 **覆核批次** 可直接逐項覆核候選，或建立回合後下載 JSON／含圖片的 ZIP 交給覆核者。ZIP 的 `assets/` 包含原尺寸案件副本，`roi` 是 normalized xyxy。

回傳方式：

1. 修改 `review_manifest.json` 內對應 `items[].review` 的 `verdict`、`reviewer`、`reason`。
2. `verdict` 允許 `pending`、`normal`、`defect`、`disputed`、`insufficient`；非 pending 需要人員與理由。
3. 不修改 case、batch、round、影像 hash、region ID 或 ROI。可只回傳已覆核項目；其他項目保持原狀。
4. 回 LV 上傳 JSON，按 **驗證並讀回覆核**。錯誤身分或过期版本整批拒絕，不會部分套用。若案件已更新，重新下載最新版清單並合併覆核結果後再回傳。

此格式為 **review-only**，並非訓練匯入格式。不自動發送到外部服務、不修改來源標註、不把 normal ROI 匯出為瑕疵框或整張負樣本。完整覆核後，可另由 **訓練交接** 按明確的 YOLO 契約匯出訓練包。

AL 帳本記錄 case／batch 連結和送覆核的唯一影像數；覆核區域數保留在 manifest。讀回不增加 legacy `n_labeled` 或產生模型指標。100 候選僅覆核 3 個時，顯示 3 已覆核／97 待覆核；訓練就緒影像仍為 0。

## 工時

可手動開始、暫停計時，以及補登／修正累計分鐘數。切換頁面不會暫停，離開前請按暫停；未暫停的 session 計時不自動入帳，重開 session 後可補登。調整保留日誌，不把開頁時間直接當成已完成工作。

用歷史案件比較查案時間與說明品質；尚未建立量測前不宣稱固定節省比例。正式模型的誤逮率與漏檢率改善，可在 **改善評估** 使用固定獨立資料另行驗收。

## 儲存與維護

- 預設資料：`output/fp_cases/`；若有 `LV_OUTPUT_DIR` 則在該目錄下的 `fp_cases/`。`LV_CASES_DIR` 可單獨指定完整案件根目錄。
- `cases.sqlite3` 保存目前案件與不可覆寫的歷次快照；`assets/` 保存依 SHA-256 命名的來源副本；`embeddings/` 保存此功能專用、依模型 recipe／影像／ROI 區分的向量快取。
- 備份請在停止服務後複製整個案件根目錄，並一起備份 `LV_OUTPUT_DIR/rounds.jsonl`。JSON 報告是匯出快照，首版不提供完整案件還原 UI。
- 同案舊版本儲存會被拒絕，重新載入後再編輯，避免覆蓋其他視窗的裁決。
- 向量計算只用本機 `dinov2_vits14` 權重，安裝位置見 [MODELS.md](../MODELS.md)。缺權重時案件仍可建檔／覆核，搜尋會說明缺少項目。

實作：`scripts/fp_cases.py`、`scripts/fp_case_search.py`、`scripts/fp_case_page.py`。驗收記錄見同目錄 `false-positive-case-implementation-report.md`。

# PRD:整張影像級瑕疵偵測(無 YOLO 標籤)

對應 User 需求:[1_user_needs/anomaly_whole_image.md](../1_user_needs/anomaly_whole_image.md)
里程碑:**M8**(瑕疵偵測 feature 收斂後的第一個新能力增量)

## 三行自問(缺一不放行)

- **誰會用**:手上只有「一資料夾**沒有標註框**的圖片」(每張圖一個主體:水果/產品/成品特寫)、想找出異常張的人。
- **不做會怎樣**:沒有 `labels/` 時工具直接跳「找不到 YOLO 物件」、什麼都不給 → 這群人**完全無法使用**本功能。
- **成功的可觀察判準**(餵給 /pm 當 AC):
  1. 選「整張影像」模式 + **無 labels** 的圖片資料夾 → **不再跳「找不到 YOLO 物件」**,跑得出結果。
  2. **物件數 == 影像數**(每張圖恰好一筆),散點圖每個點 = 一張圖。
  3. 異常分數 / 排序 / 散點 / 看圖 / 加購物車匯出 全部如常運作。
  4. 畫面**明白標示**目前是「整張影像」模式在跑。
  5. **回歸**:選有 labels 的資料夾 + 「YOLO 物件」模式 → 行為與現況完全一致(舊用法不失)。

## 目標與成功指標

- 讓「無標註圖片資料夾」也能跑完整套瑕疵偵測(建模 → 套用 → 挑樣 → 匯出)。
- 「整張影像」與「YOLO 物件」兩種來源**並存、可切換**,互不破壞。
- 衡量:無 labels 資料夾在「整張影像」模式下,N(物件)== M(影像)、不報「找不到 YOLO 物件」、散點/排序/看圖/匯出皆可用。

## 範圍(MoSCoW)

**Must**
- 新「物件來源 = 整張影像」路徑:每張可讀影像 → **一筆全幅記錄**(整張當對象),不需 `labels/`。
- `run_pipeline` 能依「物件來源」選用整張影像或 YOLO 物件;下游(embedding/分群/Normal Bank/patch/評分/散點/排序/看圖/匯出)**不變**。
- GUI ① 提供「物件來源」切換(YOLO 物件 / 整張影像);選整張影像時不要求 `labels/`;此選擇**鎖進模型**(②沿用,不被側欄改動)。
- 畫面明示目前模式(整張影像 vs YOLO 物件)。

**Should**
- 自動 fallback:選了 YOLO 模式卻偵測不到任何物件(無 labels)時,**提示**使用者可改用「整張影像」(一鍵切換);不必強制自動切。

**Could**
- 讓使用者自訂整張影像的顯示標籤名(預設 `image`)。

**Won't（本輪不做,寫入決策日誌)**
- 整張影像模式內的「多物件分別評」——整張就是一個對象(User 明說不在乎)。
- 整張影像模式的「分類頭 / 缺陷類型分類」——整張圖無缺陷類型標籤,本就不該有頭(與既有語義鎖一致)。
- 背景遮罩 / 前景分割——User 的圖主體拍滿、背景單純,不需要。

## 使用者驗收(銜接 User 文件)

- 拿一個**只有圖片、沒有 `labels/`** 的資料夾,選「整張影像」,建模 → 套用:**不報錯、跑得出每張一個分數**。
- 散點圖點數 == 圖片數;排序、看圖、加購物車、匯出 ZIP 都能用。
- 畫面看得出「現在是整張影像模式」。
- 換成有 labels 的資料夾 + 「YOLO 物件」模式 → 跟以前一模一樣。

## 給架構師的開放問題

1. 全幅 bbox 用什麼表示最不擾動下游?(YOLO 正規化 `cx,cy,w,h`,推測 `(0.5,0.5,1.0,1.0)`;請確認 `crop_bbox` 對全幅 bbox 的行為=整張圖。)
2. 整張影像記錄的 `label` / `class_id` 預設值?(單一合成類別;確保**不會誤觸分類頭解鎖**——只有 1 類本就不解鎖,但請在設計講清楚。)
3. 「物件來源」放側欄還是 ① 分頁本體?是否鎖進 `model.meta`(讓②不被側欄改動影響,與現有 model/res/score_mode 鎖定一致)。
4. patch 模式對「整張影像」是否就是「整張縮到 target_res 後切 patch」=image-level AnomalyDINO?有無邊界(極端長寬比影像)?
5. Should 的自動 fallback:偵測 0 物件時是「提示+一鍵切」還是「自動切」?(User 偏好提示即可。)

# PRD:Good/Bad 群組 patch 差異探索(製程線索發現,第 10 工具)— M19

- 需求來源:[1_user_needs/goodbad_patch_diff.md](../1_user_needs/goodbad_patch_diff.md)
- 立案:2026-07-18;狀態:PRD 完成,待放行 `/architect`

## 三行自問

1. **誰會用**:製程分析工程師——手上有同產品、拍攝條件一致(位置大致可對齊)、已依結果分成
   Good / Bad 兩個資料夾的影像(各約 100~500 張),要找「群對群的系統性局部差異」當製程改善線索。
2. **不做會怎樣**:只剩黑箱分類器(說得出是 Bad、說不出差在哪)與肉眼對看(細微差異看不出),
   製程檢討會上拿不出影像證據,AI 分析停在一個準確率數字,等於白做。
3. **成功的可觀察判準**(餵給 `/pm` 當 AC 來源):
   - (a) **植入測試**:Bad 群每張在同一固定 patch 區域植入擾動 → 該區域差異分數排名 **Top-1**,
     且整體判定=「有穩定差異」。
   - (b) **null 誠實測試**:同一母體隨機分成兩堆 → 明示「**無穩定差異**」,不給一張看起來很厲害的
     假熱圖當線索(使用者的最高信任要求:寧可說沒有,不可給假線索)。
   - (c) **零程式零標註**:選兩個資料夾 + 按一顆「分析差異」(有逐張進度)→ 差異熱圖疊圖 +
     Top-K 區域排名 + 每區 Good/Bad 對照放大 + 白話穩定度句 + 可匯出。

## 目標與成功指標(可衡量)

- **G1 植入命中**:合成注入(固定位置擾動)→ 該區域 Top-1;單元(合成陣列)+ 真實 DINOv2 E2E 皆驗。
- **G2 null 誠實**:同源隨機分兩堆 → verdict=無穩定差異,UI 顯著標示(熱圖降飽和或加警示帶,不得以
  正常樣態呈現)。
- **G3 可用性**:兩資料夾單鈕分析、逐張進度;結果含熱圖 + Top-K + 對照放大 + 每區一句白話
  (格式如「Bad 群 82% 的圖在此處與 Good 群明顯不同」)。
- **G4 匯出**:熱圖 PNG + 排名 CSV + 對照圖存到使用者**另選**的輸出資料夾;**絕不寫來源資料夾**
  (沿 [[no-dataset-writes]] 紀律;快取一律 `.lv_cache/`)。
- **G5 重跑效率**:patch 特徵快取命中時第二次分析不重抽特徵(明顯變快,可觀察)。

## 範圍(MoSCoW)

### Must
1. **雙資料夾輸入**(Good / Bad 各一),整張影像、免標註——復用 M8 `discover_whole_images` 路徑。
2. **patch 特徵抽取復用** `patch_features`(DINOv2 patch token + `.lv_cache` 逐物件快取)。
3. **每 patch 位置的群間差異分數 + 穩定度**(「幾成 Bad 在此處異於 Good 群」)。
   公式由 `/architect` 定,但**必須同時考慮群間差與群內散度**(只看平均距離會被群內雜訊騙)。
4. **null 校準與誠實判定**:內建隨機分組基準(如 permutation),輸出整體「有/無穩定差異」verdict;
   G2 為硬驗收。
5. **差異熱圖**疊回代表影像(復用 `anomaly_heatmap` 淡入疊圖慣例)。
6. **Top-K 差異區域排名** + 每區 Good/Bad **代表對照放大圖** + **白話穩定度句**。
7. **匯出**(熱圖 PNG + 排名 CSV + 對照圖)到使用者另選資料夾。
8. **逐張進度回報** + **新獨立工具分頁**(第 10 工具)——與瑕疵偵測「單張 vs 正常群」語義不同,
   沿 M13「第 9 工具獨立分類」的教訓,避免使用者混淆兩種「找異常」。

### Should
9. **整體散點旁證**:global embedding 投影散點(Good/Bad 上色)當「兩群整體分不分得開」的旁證。
   **不得**用 Good/Bad 標籤做監督投影——監督會人工推開兩群造成假分離(沿
   [[single-folder-ui-and-sumap-default]] 的例外邏輯),此處用 PCA / 非監督。
10. **對齊性提醒**:兩堆影像尺寸/長寬比不一致(→ patch grid 不一致)時,警示「結果可能不可靠」。
11. **熱圖底圖可切換**(Good 代表圖 / Bad 代表圖)。

### Could(達 appetite 即進候選)
12. 區域 ROI 傳統 CV 強化對照(對比增強/邊緣/高通)幫助人眼理解模型看到的差異。
13. YOLO 物件模式(對齊物件框做群比較)。
14. Top-K 數量、區域合併門檻等進階參數。

### Won't(v1,明砍)
- 自動影像對齊/配準(對不齊只警示,不自動修——需求前提是拍攝已一致)。
- 三群以上比較(先把兩群做好)。
- 對新影像打分(分類器用途;使用者明言不要黑箱分類器)。
- 製程參數關聯分析(使用者自列「下一步」)。
- 瑕疵類型自動判讀(判讀是工程師的專業)。
- 即時性(離線分析,幾分鐘可接受)。

## 給架構師的開放問題

1. **差異統計量與 null 校準**:用哪個統計量(須含群內散度——平均向量距離 / Fisher 比 /
   per-patch 可分性⋯由你定)?permutation 次數與顯著門檻?「穩定度 %」的精確定義?
2. **grid 一致性**:`ImagePreprocessor(keep_aspect=True)` 對不同長寬比會產生不同 grid →
   本功能是否固定 resize(犧牲長寬比換對齊)?混尺寸輸入怎麼辦(擋掉/警示/重採樣)?
3. **區域抽取**:單 patch 排名就好,還是連通區域合併(可否復用 `heatmap_to_boxes` 的
   scipy.ndimage 連通域慣例)?
4. **代表樣本選法**:每區 Good/Bad 各挑哪幾張當對照(最典型?最極端?)。
5. **熱圖底圖**:預設用哪張(中位 Good?);Should-11 的切換怎麼落。
6. **記憶體策略**:500+500 張 × patch grid(fp16 快取已有)一次載入約數百 MB——
   一次載入 vs 串流累積統計?
7. **散點旁證**:用既有哪條 global embedding 管線;投影非監督(PCA)的落點。

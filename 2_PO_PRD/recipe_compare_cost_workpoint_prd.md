# PRD:M21 做法比較可信度 + 成本工作點試算

> PO,2026-07-19。需求來源 [1_user_needs/recipe_compare_cost_workpoint.md](../1_user_needs/recipe_compare_cost_workpoint.md)。
> 上游裁決約束(已定案,見 [5_active_learning_product_review_2026-07-12/09](../5_active_learning_product_review_2026-07-12/09_半導體分析與Active_Learning下一階段功能.md)、

> **顯著性=exploratory 語義**(產線資料交換性不成立,結論標「探索性」)、
> **有群組欄位→blocked permutation**(整群同動,防批次效應假差異)、
> **成本工作點=what-if 試算,只建議不自動套**。

## 三行自問

1. **誰會用**:產線視覺檢測資料負責人——會換模型/配方/校準、要調瑕疵偵測鬆緊的人。
2. **不做會怎樣**:換做法憑單次數字+運氣,被批次效應騙;鬆緊憑感覺調,
   「漏檢比誤報貴 50 倍」這個現實無處輸入;結論拿不出去說服人。
3. **成功的可觀察判準**(→ /pm AC 來源):
   - **G1 效應檢出**:植入已知真差異(A 系統性優於 B)的合成資料 → 結論=「可信」且方向正確。
   - **G2 null/批次誠實**:①同源無差異資料 → 判「看不出來」(單次跑;假陽性率由 /pm 以
     多 seed 驗 ≤ 名目 α 上界);②效應**完全由批次造成**的資料+群組欄位 → blocked 判
     「看不出來」,且同資料不分組的天真結論會誤判(兩者對照即證明分組有效)。
   - **G3 成本曲線 exact**:手算小例(計數類)逐點 `==`,最低代價點正確;改成本比,
     曲線與最低點跟著變。
   - **G4 零副作用**:比較/試算全程不改任何生效設定(前後偵測結果不變)、零寫使用者資料夾。
   - **G5 講人話**:主結論一句白話(差多少/憑幾筆/可信或看不出來);統計名詞收「詳細」;
     無群組欄位時明講「未考慮批次,結論僅供探索」;有群組時明講「已按〈欄位〉分組」。

## 目標與成功指標

把「換做法」與「調鬆緊」兩個高頻決策,從憑感覺變成有依據:
G1–G5 全過(G1/G2/G3 為硬驗收,植入資料機器可判);使用者驗收=在瑕疵偵測工具內
完成一次 A/B 比較與一次成本試算,全程不離開 app、不動生效設定。

## 範圍(MoSCoW)

- **Must**
  - 成對比較:兩份「同一批影像、不同做法」的逐項結果 → 效應量(差多少)+ 支撐數
    (憑幾筆/幾群)+ permutation 顯著性(有群組欄位→blocked:整群同動)→
    三值結論「A 較好/B 較好/看不出來」+ 白話主結論 + method line(沿 M20 慣例)。
  - 資料不足/差異太小 → 明講「看不出來」,不硬給勝負。
  - 成本試算:輸入相對成本比(漏檢:誤報)→「鬆緊 vs 預期相對代價」曲線 +
    最低代價點標記 + 目前設定位置標記 + 各點工作量(會標記幾張);改成本比即時更新。
  - 兩功能掛進瑕疵偵測工具既有畫面(使用者平常用的地方),**只顯示與建議,
    絕不寫回生效設定**。
  - 真實 E2E(植入數字驗證,G1–G5)。
- **Should**
  - 群組欄位自動帶入:優先用 M20 metadata CSV join 的欄位,無則允許按資料夾/檔名規則;
    使用者可改選。
  - 成本 ground truth 用已確認樣本(③ 確認/標註回饋),數量不足時明講門檻。
- **Could**(本輪不做,進候選)
  - 比較結果一鍵存圖(供報告)。
- **Won't**(明砍,理由)
  - 三方以上同時比較——使用者明說兩兩即可(user 第 5 節)。
  - 歷史比較追蹤/儲存——使用者明說當下看完即可。
  - 自動選最佳設定並套用——使用者明確不要(痛點:工具自作主張);全 app
    「只建議不自動套」既有紀律。
  - 精確金額換算——相對代價即可,使用者自己換算。
  - 統計名詞主畫面顯示——收「詳細」展開。

## 使用者驗收(銜接 user 文件第 4 節)

1. 選好兩個做法的結果按一顆鈕 → 一句白話結論(差多少/憑幾筆/可信或看不出來)。
2. 資料太少或差異太小 → 看到「看不出來」而非硬判。
3. 有批次欄位 → 結論旁看到「已按〈欄位〉分組比較」;沒有 → 看到「未考慮批次,僅供探索」。
4. 輸入成本比 → 看到鬆緊-代價曲線+最低點標記;改成本比曲線即變。
5. 全程沒動生效設定;關掉試算再開,偵測結果不變。
6. 兩功能都在瑕疵偵測工具裡找得到。

## 給架構師的開放問題

1. 「兩次套用結果」的擷取與 pin 機制(A/B 槽):session 即可(不需跨重啟保存,
   user 明說不要歷史);**產品要求**:pin 動作明確、僅同資料夾可比、不同 item 集合要明講。
2. verdict 門檻的具體數字(α、最小 N、最小群組數、效應下限)與 method line 措辭
   ——技術判斷,但**「看不出來」必須是預設保守方向**(寧可說沒有,G2 精神)。
3. 群組欄位來源優先序與 UI(metadata join 欄位 / 資料夾規則 / 手動選)。
4. 成本試算的 ground truth 來源(確認樣本/回饋標註)與不足門檻的行為。
5. 成對資料的形態(分數差 vs 每項勝負)與多 item 粒度(物件級/影像級)取捨。

# PRD:M22 晶圓空間簽名分析

> PO,2026-07-19。需求來源 [1_user_needs/wafer_spatial_signature.md](../1_user_needs/wafer_spatial_signature.md)。
> 上游裁決約束(已定案):空間顯著性的 null=**within-wafer / die-mask 受限重排**
> (同片晶圓、只在既有 die 位置間重排、保缺陷數;**嚴禁全域 shuffle**)——
> 見 09/10 文件裁決;「寧可說沒有」(G2 精神)沿用全案。

## 三行自問

1. **誰會用**:半導體產線檢測資料負責人——影像=die/檢測點、CSV 有 wafer/lot+座標,
   要跟製程工程師用「晶圓的空間模式」對話的人。
2. **不做會怎樣**:空間線索斷在逐張影像層;要看模式得手動 Excel 畫圖(每片半小時,
   實務上沒人做);口頭「感覺偏邊緣」拿不出把握度,被「你確定不是剛好?」擋回。
   工具若亂報模式,狼來了之後整個工具失去信任。
3. **成功的可觀察判準**(→ /pm AC 來源):
   - **G1 植入模式檢出**:合成資料植入已知模式(邊緣圈/一團/一條線)→ 對應簽名
     判「有模式(可信)」且類型正確。
   - **G2 隨機誠實(硬驗收)**:同 die 格點、同缺陷數、隨機撒 → 判「看不出模式」;
     多 seed 假陽性率受控(≤ 名目 α 上界)。null=within-wafer 受限重排,
     測試需能證明「全域 shuffle 會誤判、受限重排不會」的對照場景至少一例。
   - **G3 地圖忠實**:die 畫在 CSV 座標的正確相對位置(邊緣 die 在邊緣、中心在中心,
     以座標極值錨定);可疑 die 與②判定一致(數量==)。
   - **G4 對不上明講**:CSV 缺座標/影像對不到列 → 明講數量與清單語彙,不默默少畫。
   - **G5 lot 並排與匯出**:同 lot 晶圓地圖並排;匯出 PNG(地圖)+CSV(每片結論表)
     到使用者另選目錄,**零寫來源資料夾**。
   - **G6 零欄位假設(使用者明示的硬約束,2026-07-19)**:同一使用者**有的情境有
     座標/lot 欄位、有的情境沒有**。工具**不得假設任何欄位存在**:
     完全無 CSV 或無座標欄 → 明講「此資料無座標欄位,無法做空間分析」+指引,
     **零輸出偽地圖**;無 wafer 欄 → 明講「無法分片」,不得默默把全部當同一片
     (使用者可**顯式勾選**「這批同屬一片」——那是使用者的斷言,工具不猜);
     無 lot 欄 → 並排功能收起並明講。每一層降級都要可觀察(訊息語彙固定)。

## 目標與成功指標

把「逐 die 判定」升到「逐片晶圓的空間模式」層:G1–G5 全過(G1/G2 為統計硬驗收,
植入資料機器可判);使用者驗收=選結果+CSV+按鈕 → 每片一張地圖+一句誠實結論
+同 lot 並排+可匯出,全程不離開 app。

## 範圍(MoSCoW)

- **Must**
  - CSV 欄位對應 UI:指定 wafer 欄、X 欄、Y 欄(自動猜測常見欄名,可改);
    lot 欄選填。join 沿用 M20 `meta_join`(filename/sha 雙鍵),對不上明講(G4)。
  - 每片晶圓地圖:die 按座標繪製,可疑/正常/未檢明確區分(G3)。
  - 三種簽名 + 隨機:**聚一團(clustered)/偏邊緣(edge)/線狀(linear)/看不出模式**,
    每片各給三值誠實結論(有模式-類型/看不出來),within-wafer 受限重排 null(G1/G2),
    附 method line(沿 M20/M21 慣例,含 exploratory 語義)。
  - 同 lot 並排檢視(lot 欄有給時)+ 每片結論總表。
  - 匯出:地圖 PNG + 結論 CSV 到另選目錄(G5,守 [[no-dataset-writes]])。
  - 資料來源:②套用結果的 verdict(=可疑)為預設訊號;真實 E2E(植入模式)。
  - **誠實降級鏈(G6,Must)**:無 CSV/無座標/無 wafer/無 lot 各層的固定訊息+
    指引;「同屬一片」顯式勾選(預設不勾);任何缺欄情境不 crash、不畫偽圖。
- **Should**
  - 點亮起的 die 顯示原始影像縮圖(需求第 2 節;技術可行性由 architect 評估,
    若 plotly 點擊回饋成本高可降為 hover 檔名+旁欄縮圖)。
  - 疑似度連續著色(score)切換。
- **Could**(本輪不做,進候選)
  - 教科書全模式(donut/半月/複合)、跨 lot 趨勢追蹤、自動根因對應(user 明說不要)。
- **Won't(明砍,理由)**
  - 自動根因判讀——user 明說模式講清楚即可。
  - 格點內插補值——user 明說抽檢有幾顆畫幾顆。
  - 地圖擬真外觀——user 明說位置對就好。

## 使用者驗收(銜接 user 文件第 4 節 + 2026-07-19 口頭補充「不要有任何假設」)

1. 選結果+CSV+指定欄位+按鈕 → 每片一張地圖,可疑 die 亮起,位置與佈局一致。
2. 每片旁一句結論(四款之一);隨機資料從不報有模式。
3. 同 lot 並排,同模式一眼可辨。
4. 對不上(缺座標/對不到列)明講數量,不默默少畫。
5. 匯出 PNG+CSV 可直接貼報告;來源資料夾零寫入。
6. (Should)點亮 die 可見原圖縮圖。
7. **沒有座標/lot 的資料**丟進來 → 得到的是清楚的「缺什麼、所以做不了什麼、
   可以去用哪個功能」,而不是錯誤畫面或一張看似有效的假地圖。

## 給架構師的開放問題

   可提案降級為 Should 並回報)。
2. 欄名自動猜測的規則(wafer/x/y/lot 常見別名)與猜錯時的 UI 語彙。
3. 地圖繪製技術(plotly heatmap/scatter?)與「點 die 看縮圖」的成本;
   多片並排的版面上限(一頁幾片、超過怎麼辦)。
4. 簽名判定的門檻(α、最少 die 數、最少缺陷數——太少寧可「看不出來」)。
5. 掛哪裡:第 12 個工具分頁 vs 瑕疵偵測內新段?(傾向獨立工具——它吃②結果但
   視覺重心完全不同;由 architect 提案。)

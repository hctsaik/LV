# 半導體工業檢測情境

## 先說限制

VisualLatent 適合做離線資料診斷、選樣與模型學習閉環，不應假裝取代 fab 既有 SPC/FDC/MES、OCAP 或設備控制。真正價值在於降低 review/label 成本、處理稀有缺陷、維護資料與模型證據鏈。

## 優先情境

| 情境 | 現場事件 | AL 如何介入 | User 與 CV 的合作 | 關鍵驗收指標 |
|---|---|---|---|---|
| AOI 候選複判與 nuisance 過殺 | 高敏感度 recipe 產生大量 false reject，人工 review 被淹沒 | 從高風險、低信心、代表性 nuisance 與少量隨機 audit 樣本取樣 | 複判員判 real/nuisance；領域工程師定義可接受變異；CV 校準模型與取樣 | overkill、underkill、review reduction、每小時有效 review 數 |
| 極端不平衡與 rare-event mining | 幾萬至幾十萬正常 die 才出現少量關鍵缺陷 | normal bank / anomaly score 先排序，再以 diversity 避免挑到近重複 | 領域專家確認 rare defect 與 hard normal；CV 維護 bank 與 unknown queue | rare-defect capture、top-K hit rate、重複送標率 |
| 新 defect mode 發現 | NPI、製程變更或長尾失效出現 taxonomy 外群聚 | 離群 → 找相似 → 整簇送 fresh label → 專家命名／裁決 | CV 負責聚簇與證據；defect 名稱及判準由領域／MRB 決定 | 新 mode 發現時間、簇純度、unknown backlog |
| Golden/normal bank 演化 | 良品外觀隨時間、材料或機台變化；誤把異常納入 bank 會污染模型 | 每輪只提議少量 bank add/remove 候選，經專家與品保簽核 | CV 提供差異與影響；領域工程師確認正常；QA 簽核版本 | bank contamination、版本可追溯、跨 lot 穩定度 |
| Tool/chamber/recipe/domain shift | 換機台、保養、recipe、照明、focus 或材料批次後分布改變 | 分層比較 domain，對漂移域設定標註配額；先判斷成像漂移還是 defect mix 改變 | 設備／製程工程師解釋事件；CV 分析 domain 與模型退化 | per-domain recall、false alarm、calibration drift |
| 回歸與 catastrophic forgetting | 新類別加入或新資料重訓後，舊層／舊 defect 表現下降 | 從歷史代表集與新域共同取樣，維持 regression audit set | CV 管 replay/evaluation；領域專家只處理實際語義衝突 | 舊類 recall 下降、new-class recall、模型版本差異 |
| Wafer map／systematic pattern 群聚 | 缺陷在 edge、ring、scratch、局部 die 群形成空間模式 | 以 wafer position 與影像 embedding 聯合分層，選少量代表 defect review | 製程工程師解讀 pattern 與 root cause；CV 不替代因果判斷 | pattern coverage、review 樣本代表性、root-cause lead time |
| 封裝／先進封裝多視角檢測 | bump、bond、underfill、substrate、X-ray/光學視角不同 | 以 component、view、station 配額與 cross-view disagreement 選樣 | 製程定義同一 unit 的視角關係；CV 維護 group identity | unit-level escape、跨視角一致性、缺 view 率 |
| Label disagreement 與邊界案例 | 操作員、班別、廠區對 defect 判準不同 | 高分歧樣本進 adjudication，不直接當作模型不確定度真值 | 標註員可標 uncertain；領域專家裁決；CV 分析分歧來源 | agreement、裁決率、instruction 版本效果 |
| 模型驗收與停止標註 | 管理者問「再標 500 張是否值得」 | 固定 probe/audit set，按回合觀察邊際增益與成本 | CV 提供曲線；QA/產品負責人決定門檻與停止 | recall/underkill confidence bound、增益/100 labels、標註工時 |

## 必須成為一等欄位的半導體資料

最小 schema 建議包含：

- 身分：`product_id, lot_id, wafer_id, die_x, die_y, unit_id, defect_id`。
- 製程：`process_step, layer, recipe_id, tool_id, chamber_id, station_id`。
- 取像：`inspection_tool, sensor/modality, magnification, view_id, timestamp, image/patch coordinates`。
- 缺陷：`defect_code, nuisance/real, severity, disposition, taxonomy_version`。
- 模型證據：`model_version, bank_version, score, threshold_version, prediction, acquisition_reason`。
- 人工證據：`annotator, adjudicator, instruction_version, confidence, skip_reason`。

缺少這些欄位時，Compare 只能知道資料夾 A/B 不同，無法知道是 lot、tool、recipe 還是 defect mix 造成；也無法保證 train/validation 按 lot 隔離，容易產生洩漏。

## 不要誤做成產品主線的情境

- 即時設備告警、OCAP 與自動停機：屬 SPC/FDC/MES 與設備整合。
- 在標註 UI 直接創建正式 defect taxonomy：通常需要製程／品質／MRB 治理。
- 只靠 embedding 漂移值決定製程異常：需要經過 domain-specific 校準與工程判讀。
- 只追求整體 accuracy：稀有缺陷會被正常樣本淹沒，應以 per-class recall、underkill、overkill 與信賴區間為核心。

## 外部實務佐證

- KLA 將 inspection、review 與 classification 結合，用來提高 yield-relevant defect 的發現效率，並明確強調抑制 systematic nuisance defect；這支持「nuisance 過殺＋review 排序」是主線，而不是附加功能：<https://ir.kla.com/news-events/press-releases/detail/121/kla-tencor-introduces-comprehensive-wafer-inspection-and>
- KLA 對 inline defect organizer 的描述同樣聚焦於移除 nuisance、依類型分 bin，讓結果可行動：<https://bbp.kla.com/>
- A*STAR 的半導體 X-ray active learning 工作直接指出 large domain shift 與 severe class imbalance，並採 rareness-aware acquisition：<https://doi.org/10.1109/ICIP46576.2022.9897842>
- 新 defect dataset 持續加入會造成舊任務退化，因此 continual-learning regression 與歷史代表集不能省略：<https://arxiv.org/abs/2407.12724>

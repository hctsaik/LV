# `09` 功能盤點比較與修正建議

整理日期：2026-07-19  
比較對象：`09_半導體分析與Active_Learning下一階段功能.md` 目前版本，與合併第二份獨立盤點前的原始分析思路。  
範圍：只記錄比較、風險與優先序裁決，不批准開發、不修改產品功能。

## 結論

目前 `09` 與原始分析約有八至九成一致。兩者都認為下一階段應優先補足：

- Typed semiconductor entity model。
- Group／time-aware split。
- Active Learning selection-bias 控制與 random sentinel。
- Risk-constrained acquisition。
- Per-domain calibration／abstention。
- Unknown、taxonomy、normal bank 的生命週期。

合併後版本新增兩個真正有價值的觀點：

1. **Cluster-level confirm 可能是剩餘最大的標註效率槓桿。**
2. **所有新功能都應延續 M19／M20 的植入訊號＋null 對照驗證紀律。**

但新增內容也有兩個優先序過度樂觀的地方：

- Tool／Recipe 顯著性分析不能在 group-aware sampling 與 selection-bias 基礎之前，直接當成可信 quick win。
- 成本敏感工作點不能在 representative audit set 與 per-domain calibration 之前，宣稱能找到最佳門檻。

因此應保留新增想法，但調整其 guardrail、依賴與時程。

## 1. Cluster-level confirm

### 新增價值

現有功能已大幅改善「選哪些樣本」，但正式標註仍多半逐張操作。對高同質 nuisance 或已知類群，採用：

```text
群組代表圖
→ 整組暫定標籤
→ 抽查中心與邊界樣本
→ 剔除例外
→ 留下 group-confirm 證據
```

有機會再降低一個量級的標註動作。

### 必要 guardrail

- 群組產生方法、embedding 與參數必須版本化。
- 不只抽群中心，也要抽邊界、離群與低相似成員。
- 設群內相似度／純度下限與最低抽查率。
- Critical defect、Unknown 與 taxonomy 邊界樣本預設不做無條件整組套標。
- 支援例外剔除、整組撤銷與重新打開。
- 帳本需區分逐張人工確認與 group-propagated label。
- 評估不能把批次傳播標籤全部視為獨立人工真值。

### 優先序裁決

可列 P0.5，但前提是 random sentinel／盲標 audit 同時存在；若用於 critical defect，應降為 P1 或提高抽查強度。

## 2. Tool／Recipe 顯著性檢定

### 主要風險

「B 機台瑕疵率是 A 的三倍」不一定代表 B 機台造成問題。可能的混雜包括：

- B 機台處理不同 product、layer、recipe 或 material lot。
- 同一 lot／wafer 內樣本高度相關，不是獨立觀測。
- 輸入資料來自 Active Learning hard-case queue，不是 production sampling frame。
- 不同 inspection tool 的 sensitivity 或 review policy 不同。
- 分母只是匯入工具的圖片數，而非實際 production units。

### 必要 guardrail

- 先完成 typed entity 與 group-aware sampling。
- 以 lot／wafer 作 blocked permutation 或 cluster-aware inference。
- 同時報 effect size、confidence interval、support 與 sampling source。
- 對 product／recipe／layer 等重要混雜因子分層或調整。
- 控制多欄位、多群組、多指標造成的 multiple-testing false positive。
- 結論必須寫成「關聯線索」，不能稱為 verified root cause。

### 優先序裁決

應併入 P1 Drift／製程事件關聯，不宜當成能在 P0 基礎完成前提供正式結論的 quick win。若要提前做，只能標示 exploratory，且不可供 release／製程責任歸因。

## 3. 成本敏感工作點

### 新增價值

把 escape 與 overkill 的相對代價轉成 threshold／risk-coverage 視圖，能讓 Business Risk 從抽象概念變成可討論的決策面板。

### 為何不能過早

期望成本只有在以下條件成立時才可信：

- 分數已在與 training 分離的 calibration set 上校準。
- 評估資料沒有被 AL selection bias 污染。
- Class prior 接近 production，或已有正式重加權方法。
- Escape cost 能依 severity、product、customer 或 disposition 分層。
- Critical recall floor 是硬限制，不會被平均成本最小化犧牲。

### 正確順序

```text
Fixed production-like audit set
→ per-domain calibration
→ risk-coverage curve
→ critical recall／underkill guardrail
→ 成本敏感工作點建議
```

### 優先序裁決

適合 P0.5，但不能與 P0 無條件平行先行；早期版本只能展示情境模擬，不得稱為 production-optimal threshold。

## 4. Wafer spatial 最小版

### 新增價值

以 `wafer_id + die_x + die_y` 顯示每 wafer 的類別、分數與群組，是把抽象 spatial requirement 轉成可用單機功能的合理方向。

### Null model 修正

單純把所有座標隨機打散可能產生假結論，因為：

- Edge 與 center 的可觀測率可能不同。
- Wafer 有有效 die mask、缺 die、重測與不均勻抽樣。
- 不同 product 的 layout 不同。
- Ring、edge、scratch line 與 local cluster 需要不同的空間假設。

建議：

- 僅在同一 wafer 與有效 die mask 內建立 null。
- 保留每 wafer 的 defect 數與原始抽樣結構。
- 依 product／layout 分層，不跨 layout 直接混洗。
- 同時報 effect size、穩定度、support 與 multiple-testing correction。
- Pattern discovery 與 confirmation 儘量使用不同 wafer。

### 優先序裁決

維持 P1。若現場能可靠提供座標與 layout mask，價值可提前；若沒有可靠座標，此功能不成立。

## 5. Similar Case 結案筆記

新增的單機 `.lv_cache` case log 很實用，但必須區分猜測與已驗證結論。建議欄位至少包括：

- `root_cause_hypothesis`
- `verified_root_cause`
- `containment`
- `corrective_action`
- `disposition`
- `verified_by`
- `closed_at`
- `evidence_uri`

搜尋結果應明示命中的是影像相似、製程條件相似，或兩者都相似；未驗證 hypothesis 不可顯示為正式 root cause。

優先序維持 P2，除非工程師 review time 已被證明是主要瓶頸。

## 6. 標註預算規劃器

用既有 probe 曲線直接外推「再標 500 張會增加多少 recall」風險很高，因為曲線會受到以下因素影響：

- 樣本取得順序與 acquisition strategy。
- 新類別或 Unknown 的出現。
- Domain shift。
- Selected-set bias。
- 曲線模型與外推區間。

較安全的產品語意是：

- 只報已觀測區間內的邊際增益。
- 用多 seed／bootstrap 顯示寬區間。
- 呈現 best／expected／worst scenario，而非單一精確值。
- 明示無法預測真正 Unknown 的發現。
- 不把預算外推當成 release commitment 或採購保證。

優先序應留在 P2。

## 7. 植入式驗收與 null 紀律

這是第二份盤點最值得全面吸收的共同原則。每個新功能都應在提案時先回答：

- 能否植入已知訊號、已知比例或已知位置？
- 無訊號的 null 是否能誠實說沒有？
- 訊號變強時，結果是否呈單調改善？
- Seed、抽樣或小幅擾動下，結論是否穩定？
- 樣本不足時，是否拒絕下結論？

但驗收方式應依功能類型區分：

| 功能類型 | 合理驗收 |
|---|---|
| 檔案、計數、schema、狀態機 | 與植入答案逐項完全相等 |
| 距離、heatmap、ranking | 命中率、排序、位置誤差與容許範圍 |
| 統計檢定 | False-positive、power、effect-size coverage 與多重檢定控制 |
| Calibration／probability | Reliability、ECE／Brier、coverage 與區間校準 |
| Clustering／Unknown discovery | 穩定度、purity／coverage、perturbation robustness，不強迫固定 cluster id |

共同規則應寫成：

> 所有功能都必須有可植入答案或可驗證不變量；能精確對帳者逐項相等，統計與模型功能則驗 power、false-positive、校準與穩定性。

## 最終優先序

```text
Typed entity
→ group/time-aware split
→ random sentinel + fixed audit set
→ risk/domain/cost constraints
→ per-domain calibration + risk-coverage
→ cluster confirm + strategy replay/shadow/promotion
→ Unknown/taxonomy/bank lifecycle
→ drift/tool analysis + wafer spatial + acquisition health
→ case management + budget planning
```

這個排序保留新增盤點的實務價值，同時避免在抽樣母體、群組相依性與 calibration 尚未可信前，過早產生看似精確的 p-value、最佳門檻或 recall 預測。

### 另外兩個最新裁決

#### 「雙方零事實錯誤」應降級措辭

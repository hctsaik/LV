# 逐頁檢視與合併建議

## 判斷原則

頁面是否合併，不以功能名稱相似為準，而看四件事：使用者是否相同、操作物件是否相同、決策是否相同、錯誤後果是否相同。若只是共同用到 embedding 或選樣，應共用後端與資料契約，不一定共用 UI。

## 頁面決策表

| 頁面 | 現在的工作 | 主要角色 | 模糊或斷裂 | 建議 |
|---|---|---|---|---|
| Visualize Embeddings | 探索群聚、離群、相似、重複、分歧與多樣性選樣 | CV 工程師 | 「選樣」近似只代表多樣性；「桶①」難懂；匯出清單／購物車多名；送標 task 隱式決定；物件送出後可能失去 bbox 脈絡 | **保留頁面**，定位為「資料探索與候選策展」。task、reason、object identity 顯性化；與其他頁共用取樣器 |
| Compare Distributions | A/B 資料分布與逐類別漂移診斷 | CV 工程師 | 漂移值缺乏可行動尺度；容易與完整度混淆；只保留原圖會失去被選物件；目前像一次性比較而非 AL 回合證據 | **保留但降級為診斷／回合參考**。不負責 SPC/FDC 排程；結果寫入 round report，選取需保留 bbox |
| 完整度熱力圖 | 找資料覆蓋缺口、缺格、稀疏區與補洞候選 | CV 工程師 | 頁名叫熱力圖但預設是 embedding；兩套補洞方式難選；採礦池、H1–H5 是內部行話；不同子流程的送標出口不一致 | **保留頁面，建議稱「資料覆蓋與補洞」**。清楚區分「屬性缺格」與「embedding 稀疏區」，統一候選出口 |
| 瑕疵偵測 | 建 normal bank、套用 anomaly score、熱圖與風險挑樣 | CV 工程師主導，領域專家提供判準 | 第③步名為送人工標但只加入購物車；①與②的確認操作外觀相似、持久效果不同；側欄設定只作用下次建模；與 Visualize 選樣策略不互通 | **保留三步工程流程**。第③步補真正送標語意；標清「暫時重評／會改模型」；與 Visualize 共用 hybrid sampler，不合併 UI |
| 匯出 | 將跨頁候選形成 YOLO 子集、manifest，或送到標註端 | CV 工程師 | 候選清單、購物車、匯出清單、CSV/ZIP 都叫匯出；「送標」與「建立訓練資料」是不同目的 | **頁面保留，概念拆清**：中央物件叫「候選清單」，動作只有「送標」與「建立資料版本」；暫時不必拆成兩頁 |
| 📥 標註回饋 | 找 pending batch，把 read-back 套入當前 session | CV 工程師 | 只作用於 `viz_records`；重新 Run 後可能消失；無 round/pool；無法清楚區分未完成、sha 不符與標籤未變 | **擴建並改定位為「標註迴圈」**：批次狀態、持久 read-back、差異、評估、下一輪都在此頁 |
| 組考卷（隱藏） | 盲標與一致性量測 | 標註管理者／領域專家 | 導航已隱藏但其他文案仍引用，形成幽靈流程；LV 不適合負責多人派件 | **功能拆分**：派件與重複標註移到 ANnoTation；LV 留 agreement/kappa 與低一致樣本清單 |
| 灰帶覆核（隱藏） | 爭議樣本與裁決 | 領域專家 | 獨立頁會把同一批次狀態切斷 | **合併到標註迴圈**，成為 `adjudication` queue，不恢復獨立頂層入口 |
| 評估（隱藏） | GT/pred、IoU、per-type recall、FN/confusion | CV／QA | 有價值但脫離回合，使用者看不出「這輪標註是否有用」 | **合併到 round report**，成為讀回後與模型發布前的 gate |

## 建議的資訊架構

```text
探索 Discover
  └─ Visualize Embeddings

診斷 Diagnose
  ├─ Compare：回合／domain 漂移參考
  ├─ 資料覆蓋與補洞：找 representation gap
  └─ 瑕疵偵測：找 anomaly / high-risk sample

行動 Act
  └─ 候選清單
       ├─ 送到 ANnoTation
       └─ 建立可重現的資料版本

學習 Learn
  └─ 標註迴圈
       ├─ 批次狀態與責任人
       ├─ read-back / adjudication
       ├─ 回合評估
       └─ 下一輪建議
```

## 應合併的是資料契約

每一個候選至少應攜帶：

- `sample_id`：內容雜湊或穩定 ID。
- `image_uri`、`object_id`、`bbox/mask`：不能只剩原圖路徑。
- `source_page`、`source_run_id`、`round_id`。
- `selection_strategy`、`selection_reason`、各分數與模型版本。
- `task_type`：fresh / verify / relabel / adjudicate。
- `pool_state`：unlabeled / queued / annotating / labeled / applied / rejected。
- `domain_metadata`：半導體情境下的 lot、wafer、die、tool、recipe、layer 等。

這個共享物件比「把三個選樣頁合成一頁」更能降低重複與誤會。

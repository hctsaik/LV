## 0. 產品方向與不可翻案的決策

### 0.1 北極星

> 在 critical-defect recall／escape 上限不退步的前提下，用最少專家時間降低 overkill；每個選樣、標註、審查、套用與模型決策都必須可追溯、可重現、可回退。

不要用 overall accuracy 當主要成功指標。第一階段至少同時報告：per-class recall、underkill／escape、overkill、review reduction、標註工時與每 100 個標註帶來的增益。

### 0.2 第一個產品切片

第一目標暫定為 **ADC 影像分類複判**，因為它能先跑通 closed loop，且不被多框幾何 read-back 阻塞：

```text
建立 lot-aware 未標池
→ anomaly／uncertainty／diversity 選樣
→ 帶 round、task、reason 送 ANnoTation
→ 標 real／nuisance／defect type／uncertain
→ review／adjudication
→ 持久 read-back overlay
→ 建立新的 immutable dataset version
→ 比較 underkill／overkill／review reduction
→ 由人決定下一輪或停止
```

若現場確認第一目標其實是 detection，必須回到產品／架構層重排 shapes read-back，不得由 PG 默默擴大範圍。

### 0.3 頁面與系統邊界

- 不合併 Visualize、完整度與瑕疵偵測三個操作 UI；它們分別負責探索、覆蓋補洞與異常風險排序。
- 合併的是候選資料契約、sha 去重、sampler、selection reason、pool／round 與 read-back。
- `📥 標註回饋` 原地擴建為「標註迴圈」中樞，不新增第七個頂層工具。
- 組考卷的派件移到 ANnoTation，LV 只留 agreement／kappa；灰帶成為 adjudication queue；評估進 round report。
- VisualLatent 負責 pool、選樣、模型／bank、資料版本與回合成效；ANnoTation 負責派工、標註、review、adjudication 與提交。
- 不做即時 SPC／FDC／OCAP、不讓工具自動停線、不在標註 UI 自動改正式 taxonomy。

### 0.4 半導體資料前提

`product / lot / wafer / die(or unit) / tool / chamber / recipe / layer / timestamp` 必須成為正式 metadata，不能只藏在資料夾名稱。抽樣、切分與驗收至少以 lot／wafer 分組，避免同 wafer 鄰近 die 洩漏。

1. **走 U-Net 流程**:每個任務卡標了需要的角色(`/pm`、`/pg` 等)。PG 角色**嚴禁**改
   `tests/`(含 conftest.py)、`3_Architect_Design/`、`4_PM_Feedback/`、`verify/`、`.claude/`、`.unet/`。
2. **判綠只認機器**:`python verify/gate.py <module>` 印 `GREEN` 才算完成,你自己說測試過了不算。
   **禁止**為了過綠而:改測試、硬編碼回傳值、加特例、`try/except` 吞錯、`skip`/`xfail`、放寬斷言。
3. **gate 印 RED 且原因是「契約檔被竄改」時,禁止跑 `--snapshot` 掩蓋**。
   這是治理事件,停工回報(見第 3 節已知事項 G-1)。
4. **絕不寫使用者的資料集**:一切快取與衍生檔案進 `.lv_cache/`(或 `output/`,依設計文件)。
   讀回標註**只能**做 overlay + append-only log,永遠不改使用者資料夾裡的 label 檔。
5. **卡住走 reverse gate**:發現設計錯、測試基礎設施跑不動、規格矛盾 → 停手,
   回報該退回哪一層(`/pg →(設計/測試錯)→ /architect 或 /pm`),**不要就地竄改**。
6. **改到共用模組**(`export_subset.py`、`label_formats.py` 等)→ 記得 nativeApp 以 submodule
   vendors 本 repo,完成後要提醒人類做雙向同步;且這兩個模組有 pure stdlib+PIL 可移植性契約,**勿加重依賴**。
7. **跑 E2E 前先清殘留 Streamlit server**,否則資源競爭造成假失敗。E2E 不進你的自主修綠迴圈
   (gate.py 已用 `-m "not e2e"` 排除),E2E 紅了就回報。
8. Streamlit 教訓(改 GUI 必讀):不要用 `st.tabs` 存流程狀態(點按鈕 rerun 會重置 tab,
   用 `st.segmented_control` + session_state,見 app.py:2187 的做法);新增 widget key 一律
   進所屬工具的命名空間前綴(如 `anomaly_*`),避免跨工具索引污染。

## 5. 建議交付順序


- 不直接修改使用者 label；只用 overlay、append-only log 與新資料版本。
- 不在 Review 雙真相尚未追查完成前，把它排成已確認 bug。
- 不在 metadata 與 group-aware split 尚未建立時宣稱通過半導體 production validation。
